02 · 准备步骤

在杭州机搭起 poc 分组

  1. 确认资源：free -h 可用内存不少于 1G；docker network ls 能看到 newapi-net。内存不够就先停在这一步，评估升级配置或换机器。
  2. 选镜像：从 LiteLLM GitHub releases 选一个带 -stable 的版本，按其 README 用 cosign verify 校验签名，写进同目录 .env：LITELLM_IMAGE=ghcr.io/berriai/litellm:vX.Y.Z-stable。
  3. 建库：把 init-db.sql 里的密码换成随机 28 位后执行：docker exec -i new-api-postgres psql -U newapi -d postgres < init-db.sql。
  4. 写环境变量：cp litellm.env.example litellm.env && chmod 600 litellm.env，填入数据库密码、master key 和上游 key。PoC 阶段的 CONTENT_SAFETY_URL 填 http://content-safety-mock:8088/moderate。
  5. 启动：docker compose --profile poc up -d，然后执行 curl -s 127.0.0.1:4000/health/readiness，应返回 "db":"connected"。
  6. 打开内容安全护栏（仅 PoC）：把 config.yaml 里 cn-content-safety 的 default_on 改成 true，然后 docker restart litellm。
  7. 建 team 和 key：LITELLM_MASTER_KEY=… sh bootstrap_teams.sh，key 只记在本机，不要粘贴到任何聊天或文档里。
  8. 配置 New API：按下一节的表格操作。
  9. 跑自动化用例：在任意能访问 New API 的机器上设置环境变量后执行 python3 poc/poc_check.py，然后单独执行 python3 poc/poc_check.py T5。
03 · New API 配置

poc 分组的渠道与用户

配置项值原因
分组新建 poc，倍率与 default 相同和真实用户隔离
渠道 1（OpenAI 系）类型 OpenAI；Base URL http://litellm:4000；密钥填 poc team key；模型填 config.yaml 中的 model_name；分组选 poc只有 OpenAI 等类型会强制带 include_usage，用「自定义」类型的话流式请求拿不到 usage
渠道 2（Claude）类型 Anthropic Claude；Base URL http://litellm:4000；密钥同上；模型填 Claude 系列避免 Claude→OpenAI→Claude 两次协议转换
直连渠道（回滚演练用）同 poc 分组，指向原上游，默认禁用启用状态下会被重试选中，从而绕过护栏和预算
测试用户与令牌只属于 poc 分组；充少量额度poc_check 通过管理接口读取它的额度
系统设置 · 自动重试状态码保持默认（不含 400）护栏返回 400 时才能不重试、直接退额度
系统设置 · 自动禁用状态码保持默认 401轮换 LiteLLM key 时，先改渠道再吊销旧 key
