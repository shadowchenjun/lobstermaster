把海量素材，

02 / CORE PIPELINES

先理解素材，再组织叙事。

PIPELINE A / 建库

长视频 → 可检索的素材结构

  1. 接收与去重

    可续传分片、完整性校验、SHA-256、来源与使用权信息。长视频和短视频共用资产实体。

  2. 标准化预处理

    ffprobe 技术探测，原片只读保留；生成代理、音频与预览，记录原片和代理时间映射。

  3. 镜头、窗口与关键帧

    场景边界与长镜头窗口分开标记；关键帧保留精确时间位置，目标增加代表性与质量评分。

  4. 多模态理解

    ASR 识别语音、OCR 识别画面文字、VLM 描述人物 / 动作 / 环境；时间范围、置信度与模型版本一起存储。

  5. 标签治理与索引

    本体、同义词、人工审核、纠错版本；文本和向量索引可由主数据重建。

PIPELINE B / 创作

自然语言 → 可编辑的长视频

  1. 需求转为结构化 Brief

    提取主题、受众、时长、风格、画幅、必须出现和禁止出现的内容；矛盾条件需澄清。

  2. 章节规划与多路召回

    把长叙事拆为章节目标；关键词、标签和多模态向量召回，先过滤权限与版权，再重排。

  3. 全局分配素材

    控制跨章节重复、主体连续、景别变化和可用时长；缺素材要报告缺口，不能靠无意义循环补齐。

  4. 编译为 Timeline

    确定源入 / 出点、位置、音轨、字幕与转场。服务验证合法性，用户可以局部替换并保存新版本。

  5. 渲染、质检与交付

    先代理预览再高质量输出；片段缓存、音画检查、来源清单。一条需求可产生多个独立版本。

长视频不适合“整片一次丢给模型”。当前 VLM 已按镜头逐段保存结果，ASR 按时间片映射，OCR 按证据帧处理；执行仍是本地顺序 BackgroundTasks，中断会标记失败，需要人工重试，尚不具备生产 Worker 的自动接管能力。
03 / DATA & LINEAGE

统一目录，不是五个孤立文件夹。

Asset · 原始视频或图片

ID、内容哈希、技术元数据、来源、权限、状态。

一对多 ↓ 派生关系
Rendition · 代理 / 音频 / 缩略图

处理配置、对象地址、版本、校验和；原片不被覆盖。

视频一对多 ↓ 时间范围
Shot / Segment → Keyframe

镜头或分析窗口、入出点、边界来源；关键帧记录所属范围和时刻。

关联 ↓ 可审核的证据
Annotation / Tag / Embedding

ASR / OCR / VLM / 人工来源、置信度、版本、标签关系与索引版本。

DESIGN RULES

必须守住的数据边界

  • 短片段优先是逻辑范围。引用源资产与时间范围，需要下载或渲染时再物化。
  • 标签不是模型的“事实担保”。区分观察、推断、人工确认；保留可回看证据。
  • 时间以源为锚点。目标记录 timebase / PTS 与代理映射，界面毫秒只是展示层。
  • 项目保存引用和版本。Project → Brief → Plan → TimelineVersion → RenderJob，成片能追溯原始片段。
  • 检索索引是派生数据。数据库与对象存储为事实源；模型升级后可以逐步重建索引。

现有表为 assets、shots、uploads、audit、projects、timelines、renders；完整 Rendition、Annotation、本体、租户关系仍需扩展。

05 / API & EXECUTION CONTRACTS

模型负责建议，程序负责兑现。

已经运行的核心接口

  • POST /v1/uploads 创建分片会话；上传分片、查询状态、完成合并。
  • GET /v1/assets/{id}/shots 返回关键帧、镜头转写和 OCR 证据。
  • POST /v1/assets/{id}/text-analysis 手动运行已配置的本地 ASR/OCR。
  • PATCH /v1/shots/{id}/annotations 带 base_version 保存人工标注。
  • GET /v1/taxonomy 返回版本化标签分类、概念与同义词。
  • POST /v1/search/index 经授权重建 Shot 文本向量。
  • POST /v1/search 默认本地关键词，可选经授权的混合检索并返回分项分数。
  • POST /v1/projects/{id}/plan 当前为选材顺序编排与缺口报告。
  • PUT /v1/projects/{id}/timeline 保存不可变新版本。
  • POST /v1/timelines/{id}/renders 返回渲染任务 ID，随后轮询状态并下载。

Timeline 的最小可执行契约

{
  "schema_version": "0.1",
  "clips": [{
    "id": "clip-id",
    "shot_id": "existing-shot-id",
    "source_in_ms": 12000,
    "source_out_ms": 18000,
    "start_ms": 0
  }]
}

以上是结构示例，不对应实际资产。当前单视频轨要求从 0 连续排列、clip ID 唯一、源范围有效。后续扩展多轨、转场、字幕与音频时必须升级契约版本和验证规则。

为什么不让大模型直接操作 FFmpeg？

大模型输出受约束的 Brief、候选镜头和编辑决策，后端验证素材存在、范围、权限、时长、版本与预算，然后编译为固定参数数组。这样失败可定位、结果可复现，也避免提示注入变成命令执行。

检索与长视频规划如何验收？

建立带人工相关性标注的中文查询集，评估 Recall@K、nDCG、硬约束违反率与检索耗时。创作评估章节覆盖率、素材重复率、时长缺口、主体连续性和人工可用率；没有标注集与实测，就不声称“语义理解已达到要求”。

06 / RELIABILITY & SECURITY

长任务必须可恢复，素材必须可控。

任务可靠性

  • 目标状态：QUEUED → RUNNING → READY / FAILED / CANCELLED；分析节点保存检查点。
  • 任务幂等键包含资产哈希、操作版本、配置与模型版本，参数变化使缓存失效。
  • 重试区分网络暂时故障与不可恢复输入错误，配置预算、次数和超时。
  • 原子发布中间产物，先校验再 READY；缓存损坏应重建。
  • 当前重启只标记中断失败，不具备自动恢复；Temporal 接入后另测故障恢复。

权限、隐私与内容治理

  • 当前仅本机单用户、同源访问，没有认证，不可直接暴露公网。
  • 生产阶段由服务端身份确定租户；检索、预览、下载和任务均执行权限检查。
  • 外部模型默认关闭，显式配置允许传输后才可调用；秘钥不进入浏览器与日志。
  • 素材文字及模型输出视为不可信数据，不能覆盖系统指令、执行代码或任意读取文件。
  • 维护来源、授权范围、保留期与删除传播；索引和缓存也受删除与权限更新约束。

容量和 SLA 是待验证目标：接口允许的大文件上限不等于已经做过对应体量测试。小时级视频、VFR / HDR / 多音轨、磁盘耗尽、生产并发与恢复必须通过独立黄金集和压力测试。

架构决策记录

ADR-01：先采用模块化单体和独立 Worker 边界，不立即上全套分布式设施。

ADR-02：原片只读、代理独立、镜头逻辑引用；完整 PTS 映射作为后续准确性门槛。

ADR-03：模型能力通过 Provider 接口接入，未配置不能返回模拟语义。

ADR-04：Timeline 是渲染唯一输入契约，保存不可变版本。

ADR-05：保留现有 Vue 原型和真实工作台；是否转 React / Next.js 需独立评审，当前不静默改变规格。
