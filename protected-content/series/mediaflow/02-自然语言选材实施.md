# 自然语言选材与章节编排 · 本轮实施

本轮继续由三个 Luna 子 Agent 并行实现需求解析、推荐服务与工作台；主 Agent 负责章节编排、模块审查和端到端集成。

## 用户流程

1. 素材上传后生成真实关键帧；给素材补充描述与标签。
2. 在视频组接页输入需求，解析明确的时长与画幅，复核歧义提示。
3. 推荐服务按已存描述、标签和文件名匹配，返回关键帧与命中词。
4. 用户确认候选，生成时间线，可重新排序，保存新版本后渲染。

当前推荐依赖已有文本和有效标注：人工标注优先，无人工版本时使用已持久化的 `VLM_UNREVIEWED` 标注。S08 修复了 AI 标签未参与排序/排除条件的问题；同词标签命中人工权重 10、AI 权重 6，描述 3、文件名 2，均为规则权重而非置信概率。AI 原始证据与未审核来源保留，不会把被人工纠正的标签重新混入候选。

推荐本身不调用模型，不具备未标注画面理解、向量相似度或自动编剧能力。标签排除是文本约束，不能保证模型未识别出的对象不在原始画面中。

## 接口

- `POST /v1/intent/parse`：完整保留原始需求，解析明确时长与画幅。冲突、否定、素材区间与模糊表达返回提示，默认值需用户复核。
- `POST /v1/recommendations`：输入 `prompt`、`duration_ms`、`exclude_tags`，仅检索 READY 镜头；返回候选、匹配词、排序分、可用时长与缺口。
- `POST /v1/chapters/plan`：输入明确的章节标题、需求与时长，按章节顺序分配素材。相同镜头最多分配给一个章节；无法填满的章节保留缺口。

章节请求示例：

```json
{
  "chapters": [
    {"title": "开场", "prompt": "海边日出", "duration_ms": 20000},
    {"title": "收尾", "prompt": "城市夜景", "duration_ms": 15000}
  ],
  "exclude_tags": ["水印"]
}
```

章节接口返回连续 Timeline，可作为现有项目时间线接口的输入。全部无匹配时 `timeline` 为 `null`。章节结构由调用方明确提供，尚未接入自然语言自动分章；本轮章节能力以 API 提供，工作台仍使用单段需求选材流程。

## 实现边界

- 推荐使用本地文本规则，当前仍需扫描 READY 镜头。大规模索引与相关性评测是下一阶段工作。
- 章节按输入顺序优先分配，属于贪心策略，不代表全局最优；同镜头剩余部分不会重新分配给后续章节。
- 目标时长超过可用素材时报告缺口，不自动循环素材或拉伸视频。
- 当前粗剪只输出 640×360、16:9、25fps，保留源音频；其他画幅、字幕、配乐、旁白和高清渲染待实现。
- 不触发外部模型服务。视觉建议仍需要 Provider 配置及人工发起。

## 验收证据

`tests/test_creation_flow.py` 使用真实图片入库并人工标注，从自然语言解析、推荐、时间线保存一路渲染到真实 MP4；同时确认排除标签后不返回对应素材。

`tests/test_chapters.py` 验证跨章节镜头去重、短目标裁切、连续时间线和无素材时的明确缺口。其他解析及 API 回归随各模块维护。

浏览器控制服务当前报连接策略加载错误，本轮不能将代码检查和 API 测试当作浏览器视觉验收。
