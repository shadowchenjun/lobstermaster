01 / EXECUTIVE SUMMARY

当前能做什么，目标要做到什么。

本地开发版

当前已经跑通

  • 真实入库：视频和图片上传、哈希去重、分片续传、元数据探测。
  • 真实预处理：FFmpeg 代理、镜头或分析窗口、最多 3 个差异化候选关键帧。
  • 多模态基础：可选 VLM 多帧标签、本地 ASR 时间片对齐、关键帧 OCR 与证据保存。
  • 标注与搜索：人工标签优先，taxonomy-v1 同义词、文本检索与可选 Embedding 混合召回。
  • 创作闭环：需求解析、明确章节分配、时间线版本、带音轨 MP4 粗剪。
  • 任务基础：数据库快照、CAS、事件序列、租约 token、过期恢复方法。

完整系统目标

  • 小时级长视频稳定入库，ASR、OCR、视觉理解与完整时间码关联。
  • 关键词、标签、向量和重排组成可评测的混合检索。
  • 自然语言自动生成 Brief、脚本、章节、旁白、分镜和素材覆盖报告。
  • 独立 Worker 从检查点恢复，支持高清、字幕、转场、局部重渲染和自动质检。
  • 企业权限、版权、来源、审计、成本和多租户能力进入生产验收。

结论：现在是一套可操作、可测试的本地开发产品，核心短素材和可配置多模态基础闭环成立；Phase 0–4 的完整退出条件尚未通过，不能按 86 项测试外推到 100 小时素材、真实模型质量或生产 SLA。

02 / END-TO-END JOURNEY

完整业务流程。

每一步保留资产 ID、时间码、版本、模型来源和任务事件，方便定位失败并局部重算。

03

镜头理解

04

统一索引

06

选材编排

07

05 / ASSET MODEL

一套目录，连接五类素材。

视频片段不是重复拷贝的文件，而是对原片时间范围的逻辑引用。

Asset

长视频、短视频、图片、音频或文本附件；记录哈希、来源、权限和状态。

→ 1:N
Shot / Segment

原视频上的时间范围，包含切分来源、入点、出点和关键帧。

→ 证据
Annotation

人工、ASR、OCR、VLM 标签与描述；记录来源、版本和审核状态。

Rendition

代理、音频、缩略图和可重建缓存，配置与原片分开保存。

→ 检索
Embedding / Index

按模型和预处理版本隔离的向量与文本索引。

→ 创作
Project / Timeline

Brief、章节、镜头映射、不可变版本、渲染和来源清单。

标签优先级

人工标签有版本时作为有效标签；否则使用已保存的 VLM_UNREVIEWED 结果。推荐保留 AI 原始证据，但人工纠正后不会把旧 AI 标签重新混入检索文本。

时间码原则

Shot、关键帧、ASR 和 OCR 都必须回到原片时间轴。当前代理为 CFR，但完整 VFR 逐帧 PTS 回切仍是待验收项。

06 / PRODUCT MAP

页面与用户功能。

真实工作台 + 完整原型

素材建设

  • 视频/图片选择、分片上传、续传和处理状态。
  • 资产列表、技术信息、代理预览、镜头和多帧关键帧。
  • 人工描述与标签编辑、版本冲突提示、AI 标注来源。
  • 关键词/标签检索和排除条件。

视频创作

  • 自然语言解析时长与画幅，展示歧义和默认值。
  • 推荐 Shot、关键帧、命中词、匹配分和时长缺口。
  • 选择/排序镜头、生成 Timeline、保存新版本。
  • FFmpeg 粗剪、任务状态和 MP4 下载。
真实工作台与界面原型有什么区别？
根路径 / 是连接 FastAPI 的真实开发工作台。/prototype/ 保留完整的 13 页交互设计，用于功能和视觉规格参考，其中仍有模拟数据与模拟任务，不能作为后端能力证明。
上传后会自动识别什么？
默认自动完成媒体探测、代理、Shot/窗口和关键帧。配置本地 ASR/OCR 后，默认继续抽取 16kHz 单声道音频、按时间片对齐转写，并对每镜头最多 3 张证据帧做 OCR；可用环境变量关闭自动文本分析或在详情页手动重跑。视觉语义需要配置 VLM，并由用户明确允许外发精选帧。未配置能力不会生成假结果。
自然语言如何变成视频？
当前解析明确的时长、画幅和文本条件，再按已有有效标签推荐镜头，用户确认后生成单轨 Timeline 并粗剪。目标版本还会生成脚本、章节、旁白、分镜，执行向量检索和跨章节全局分配。
