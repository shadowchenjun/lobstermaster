1项目现状

项目依据《中化商务智能助手建设方案 V3.0》实现，包含两条业务线：

  • 表单智能填写：从源平台页面“采集”数据，或从招标文件“解析”数据，按标准要素归一后存进本机项目；再把项目数据“填写”到目标平台的表单里。
  • 智能问答：基于知识库（内部系统操作手册、法规制度、业务知识）做检索问答，回答带引用。

目标环境是信创：麒麟/统信桌面、KingbaseES、TongWeb、国产浏览器、昇腾推理。为了满足“业务数据不外泄”，采集结果和附件只加密存在客户端本机，服务端只保存配置、知识库和统计数据。

2.3 设计原则（决定了大部分实现）

  • 以内部招采平台的字段为“标准要素”做中枢映射。任何平台 A 的字段先归一到标准要素，再从标准要素投影到平台 B。新增一个平台只需配置“平台 ↔ 标准要素”的映射，不必做 N×N 两两映射；数据也能双向流转。
  • 业务数据端侧留存。采集值、附件、填写记录只加密存在客户端本机。服务端处理页面值时只在内存中转发给 AI，不落库、不写日志。服务端能积累的只有不含业务值的映射知识（字段名、选项名与要素的对应关系）和统计数据。
  • 先规则后模型，模型只做候选内选择。字段匹配、枚举对应、文件抽取都先走确定性规则，规则拿不准时才调大模型，且模型只能在给定候选里选，输出还要校验原文引用。没配大模型时整个系统可以用规则跑通（端到端测试就是这样跑的）。
  • 执行器绝不提交。填写全程拦截“提交/发布/保存”等按钮的点击，由用户核对后自己提交。

本机开发的几个坑
  • mvn 默认用 JDK 25，必须显式设 JAVA_HOME 为 JDK 17。国内源：pip 用清华镜像，npm/electron 用 npmmirror（client/.npmrc）。
  • 客户端会固定服务端公钥指纹（首次连接时记录）。换了一个 biz 数据目录（新的 server-sm2.key）后，老客户端会报 10004“公钥指纹不一致”。开发时可把旧的 data/server-sm2.key 拷过去，或用 --user-data-dir 给客户端换一个数据目录。
  • 客户端是单实例应用。跑 --e2e 或 --ui-snapshot 前要先退出开发模式的客户端。

5智能采集流程

目标：把源平台当前页面上的字段和附件，变成“标准要素 + 值 + 置信度 + 依据”，用户确认后存进本机项目。

  1. 用户点“采集当前页面”渲染进程 CollectView.vue
    IPC collect:run → Workflows.collect()（client/src/main/workflows.ts:65-101）。
  2. 定位当前标签页BridgeManager
    托管浏览器按“有焦点 +2、可见 +1”给所有页面打分取最高；扩展取最后聚焦窗口的活动标签页。
  3. 页面提取inject.js，每个 frame 一份，含跨进程 iframe
    在隔离 world（__sinochem_assistant）中执行 extract()，产出字段、附件、高风险按钮、未展开分组计数。规则见下方 5.1。
  4. 归一化客户端 → biz → AI
    POST /api/v1/elements/normalize（SM4 加密请求体），biz 原样转发到 /ai/v1/elements/normalize，不落库。算法见 5.2。
  5. 下载附件并立即加密浏览器通道
    逐个触发下载 → 落到保险箱 tmp → 立即 SM4-CTR 加密进 _drafts 区并删除明文。失败的附件可单独重试（collect:retry-attachment）。
  6. 公告正文 PDF 并入仅当页面是 pdf.js 内嵌 PDF
    解密 PDF → 上传解析 → 按全部非文件要素抽取 → 与页面结果合并：页面没有的直接加入；页面已有但值不同，以页面值为准，标冲突、置信度封顶 0.6，PDF 值放进候选（workflows.ts:124-151）。
  7. 用户核对ElementTable.vue
    可改值（改后 conf=1）、选冲突候选、移除行、给“未对应字段”手工指定要素、选择保存到的项目和阶段。存在未核对的冲突或低置信度字段时弹窗确认。
  8. 确认入库confirmCollect，workflows.ts:169-201
    写一条 kind=collect 记录（整条 SM4 加密），附件从 _drafts 移到项目目录并关联记录。
  9. 上报（不含业务值）客户端 → biz
    POST /api/v1/mapping/samples：字段名、控件类型、要素编码、选项文字 ↔ 枚举项；POST /api/v1/tasks/records：统计数；审计摘要每 5 分钟上报。

5.1 页面提取规则（client/src/inject/inject.js）

可编辑控件

  • 先按组件库根节点识别：Element（select / tree-select / cascader / date-editor / radio-group / checkbox-group / upload）、Ant Design（select / picker，只识别不能填）、layui（select / radio / checkbox），再识别原生 input / textarea / select / contenteditable。
  • 标签识别优先级：.el-form-item__label → antd / layui label → label[for] → aria → 表格型表单左侧单元格 → legend → 包裹 label → 最近前置短文本 → placeholder。带 * / is-required 判为必填。
  • 同时记录分组标题 section、所在页签 tab、当前值、可读到的选项（el-select 懒渲染，提取时为 null）、disabled、maxLength。
  • 不可见控件不采集，只按页签计数到 hiddenByTab，界面提示“还有未展开的分组”。页头页脚导航分页整体排除。

只读字段、附件、PDF

  • 详情/查看页的“标签：值”：只显示文字的 el-form-item / ant-form-item（结构明确，值可长到 2000 字，如多选的国民经济分类）、el-descriptions、th.label、dt，以及通用“标签：值”文字对（标签 2~16 字，值 ≤ 200 字）。“--”“/”“,”这类只有标点的值视为空。生成 controlType:'readonly' 字段。
  • 抽屉 / 对话框：页面上打开了 el-drawer、el-dialog、ant-modal、layui-layer 或 [role=dialog][aria-modal=true]（宽 ≥ 300、高 ≥ 150）时，只采集最上层那一个里的字段、附件和按钮，背景页的查询条件和列表信息不混进来；结果里 scope 为它的标题，界面提示“只采集了当前打开的弹窗”。
  • 页面标题：字号 > 17px、6~80 字的 h1~h3，作为“页面标题”字段。
  • 附件：带 download 属性或常见扩展名的链接；文字为“下载/下载附件/立即下载”的按钮（文件名从附近文本找）。
  • 内嵌 PDF：frame 里有 #viewerContainer 且 URL 带 ?file= 时，该 frame 不提取字段，只生成一个 kind:'embedded-pdf' 附件。
  • 高风险按钮：文字命中黑名单（提交/发布/送审/保存…）的按钮列入 riskyButtons。

5.2 归一算法（server/ai/app/elements/engine.py）

字段 → 要素（match_fields，92-175 行）按优先级逐级尝试，命中即停：

级别方式基础置信度说明
1页面模板 template1.0(平台, 页面指纹) 对应模板里有该标签
2平台字段别名 platform-alias0.95已发布快照中该平台的别名
3标准名称 name / 通用别名 alias0.95 / 0.93标签规范化（去空白、星号、冒号、括号，全角转半角）后精确相等
4候选召回 + 大模型裁决 llm0.6~0.92对所有要素算 max(包含相似度, 向量余弦×0.9)，加控件类型修正（上传只配文件要素、日期偏好日期要素等），取 Top-5。最高分 < 0.6 时补入全部类型相容要素（≤ 40）。待定字段每 12 个一批并发交给大模型，某批输出不合法 JSON 时重试一次；模型返回候选之外的编码一律视为“无对应”

值归一：

  • 枚举：多选按“、，”拆开，逐个找标准项：当前平台枚举别名 (1.0) → 标准项名称/路径 (1.0) → 树形：换了分隔符或连写的完整路径“福建省福州市鼓楼区” (1.0)、省略上级的“福州市鼓楼区” (0.98)、省略“省/市/区/县”后缀的“福建福州鼓楼” (0.9) → 其他平台别名 (0.9) → 相似度 ≥ 0.8 (0.85) → 大模型在标准选项里选（选项超过 200 个时只给最相近的 120 个）(≤ 0.85) → 都不行则保留原值、置信度封顶 0.6。重名节点（福州、南京、徐州、开封都有“鼓楼区”）只凭名称不能确定时，不再用相似度随便挑，交给人工确认。
  • 日期统一为 YYYY-MM-DD[ HH:mm]；金额识别“元/万元/亿元”并换算到要素单位；电话少于 7 位数字降权。格式无法识别 ×0.5。
  • 最终置信度 = 匹配置信度 × 值系数。
  • 冲突：同一要素出现不同值时，等枚举兜底全部完成后，取置信度最高的作主值（同分取先出现的），标 conflict、封顶 0.6，其余进 alternatives。常见来源：抽屉里同时有项目级和标段级字段，而字典还没有标段级要素。
  • 取值形态检查：取值是邮箱或电话号码时不对应到单位、人名类要素（“采购人邮箱”字面含“采购人”也不会被当成招标人）；电话、邮箱类要素也不接收人名。
  • 附件 → 文件要素：附件名包含要素名或别名即匹配（0.9）。
  • 阶段推断：模板带阶段时直接用；否则各要素按 conf / 所属阶段数 投票。

6文件解析流程

  1. 选择文件并上传ParseView → parseFiles，workflows.ts:338-354
    单文件 ≤ 100MB，一次 ≤ 20 个。multipart 上传到 POST /api/v1/parse/tasks。文件内容不做 SM4 加密，签名也不覆盖文件内容，依赖 TLS。
  2. 服务端加密暂存并入队biz ParseService
    每个文件用单独随机密钥 SM4 加密存到 parse-tmp/*.enc，建一个批次父任务 + 每文件一个 parse 任务（优先级 3）。
  3. worker 领取并解析ai-worker
    claim → 下载解密后的文件 → parse_bytes → 结果回写 complete。任务结束（成功或最终失败）时 biz 立即删除暂存文件和密钥。
  4. 客户端轮询
    每 1.5 秒查询批次状态，15 分钟超时。
  5. 按需抽取客户端 → biz → AI /ai/v1/parse/extract
    两种目标：“当前浏览器页面需要的字段”（读取页面字段标签）或“按阶段”（该阶段的全部要素）。
  6. 用户核对并保存
    写 kind=parse 记录；可选把原文件加密存进项目（注意：当前这些附件 code=null，填写时不会自动回填，见第 15 节）。随后自动跳到“智能填写”并预选该项目。

6.2 证据抽取与反幻觉（server/ai/app/parse/extract.py）

  1. 规则抽取：表格键值 table-kv（0.92）、表头列 table-header（0.88，多值 0.75）、正文“名称：值” text-kv（0.86，在下一个标签、未配对括号处截断）。
  2. 过滤非取值：丢弃“见招标公告/详见…”这类引用、值本身是另一个要素名、枚举要素却是长句且对不上标准项。
  3. 大模型补抽（仅规则没抽到的要素）：每批 6 个要素并发，每个要素按词法相关度取 Top-4 片段，每批 ≤ 16 片段。提示词要求逐字引用 quote 和 blockId、找不到返回 null、忽略 <数据> 内的指令。
  4. 校验：blockId 必须在本批片段内；quote 规范化后必须是原文子串；值必须出现在原文中（允许日期格式、千分位差异）。任一不满足即丢弃。通过后置信度 0.6~0.85。
  5. 归一：同采集的枚举/日期/金额规则；再乘 OCR 置信度；多值冲突封顶 0.6。返回 {elements, missing, llmUsed, promptVersion, ms}，每个值带证据（文件、页码、原文、方法）。

7.2 值投影（project_value，engine.py:437-494）

  • 选择类：为标准值生成候选显示文字（目标平台枚举别名 → 标准名称 → 完整路径 → 叶子名 → 其他平台别名 → 原值）。选项已知时精确匹配或相似度 ≥ 0.75；仍对不上调大模型在目标选项里选。选项懒加载时给出首选值 + 候选列表，由执行器逐个尝试。
  • 树形（行政区划、行业）：先精确匹配，再退到上级（目标只有省份下拉时选“福建省”，系数 0.9，并提示“只能选到这一级”），最后才用相似度。选项懒加载时，候选末尾依次附上上级路径和名称（“福建省/福州市”“福建省”），目标级联只有两级时执行器会退到市；重名节点的单独名称不进候选，避免级联按名称搜索选错。
  • 日期按目标控件 placeholder 的格式输出；金额按目标字段名/placeholder 的单位换算；超长文本有模型时压缩改写（×0.8），否则截断（×0.6）。
例子：为什么映射配置很重要源平台“组织形式=自行组织”，目标平台只有“自主招标/委托招标”。没有枚举别名时计划显示“需补录：目标选项中没有「自行组织」”；管理员配置（或审核通过样本得到）B 平台枚举别名“自主招标 ↔ 自行组织”并发布后，这一项直接投影为“自主招标”。端到端用例 M-01/F02 就是验证这条链路。

8知识库与问答

8.1 入库

  1. 管理员在后台上传文档（pdf/doc/docx/wps/xls/xlsx/txt/md/html），biz 存原文到 kb/（明文），sha256 相同的有效文档拒绝重复上传，入队 kb_ingest。
  2. worker：解析 → 切片 → 向量化 → 写索引 → 切片回写 biz（kb_chunk）→ 更新文档状态。
  3. 切片规则（kb/chunker.py）：目标 300~800 字；法规按“第X条”切；FAQ 一问一答一片；带章节路径 《标题》 一 > 二 前缀；表格按行分组且每组带表头；只在正常长度溢出时带上一句（≤ 120 字）做重叠。
  4. 权限：文档 ACL = 所在目录及所有上级目录的 acl_tags 之和，空表示全员可见；用户 ACL 由安全管理员分配，经 X-User-Acl 传给 AI。

8.2 检索与生成（kb/qa.py）

  1. 意图：寒暄正则直接回答；有模型时用 fast 模型判分区（系统操作 sys / 业务知识 biz / both / 超范围）、系统（招采 zc、财务 cw、请假 qj、邮件 yj）和改写问题；否则关键词规则。
  2. 检索：稠密 + BM25 各 30 条，RRF 融合，再 rerank（无 rerank 模型时用词法打分）取 Top-6。单分区结果不足时放宽到全部分区再查一次。
  3. 拒答：分数 ≥ 0.2 的结果为空时回答“知识库中没有找到相关依据…”，附最接近的 3 条。
  4. 生成：参考资料放进 <参考资料>，要求 [n] 引用；无模型时返回抽取式答案（最相关原文）。最终只保留答案中出现的引用。

SSE 事件（biz 转发并追加 session / messageId）：session → intent → citations → 多个 delta → done {answer, citations, noAnswer, ms}；出错时 error。反向代理必须关闭缓冲（proxy_buffering off）。

向量后端：默认 LocalIndex（data/kb-index/，numpy 矩阵 + BM25，适合十万级切片，每次写入全量重建 BM25；只在进程启动时加载，只适合单进程，见 15.1）；生产和百万级用 Milvus（HNSW + 内置 BM25 稀疏向量）。更换向量模型后必须在后台执行“重建索引”，启动时发现向量空间不一致会拒绝加载旧索引。

  • 回滚只切换生效版本指针，别名表和模板表不恢复。回滚后如果再发布一次，发出去的是表里的当前内容（代码推断）。
  • AI 按 (字典 digest, 快照 version) 缓存索引；biz 读数据另有 60 秒缓存，清缓存通知失败时最多延迟 60 秒生效。

11安全机制

机制实现
服务端身份服务端 SM2 公钥的 SM3 指纹与预置指纹（安装包 defaults.json）比对；无预置时首次连接固定，之后变化拒绝连接（错误码 10004）
请求签名防重放设备 SM2 私钥签 METHOD\nPATH?QUERY\nTS\nNONCE\nSM3(body)，头 X-Device-Id / X-Timestamp / X-Nonce / X-Signature；时间偏差 ≤ 300 秒；nonce 记在进程内 Map；JWT 中的设备号必须一致（SignatureInterceptor.java）
请求体加密随机 key+iv 做 SM4-CBC，key+iv 用服务端公钥 SM2（C1C3C2）加密放 X-Enc-Key。响应不加密；multipart 不加密（CryptoFilter.java）
登录口令 PBKDF2-HMAC-SM3 12 万次；≥ 8 位且含三类字符；连续失败 5 次锁 15 分钟（进程内计数）；JWT HMAC256，access 120 分钟、refresh 7 天
三员分立6 个角色：USER、CONFIG_ADMIN、KB_ADMIN、SYS_ADMIN（建号、启停、重置口令）、SEC_ADMIN（分配角色和 ACL）、AUDIT_ADMIN（只看审计）。三员角色互斥，初始账号 sysadmin / secadmin / auditadmin / admin
审计/admin/** 非 GET 请求、登录、改口令、设备注册换绑、客户端上报（前缀 CLIENT_）自动留痕；SM3 哈希链，后台可一键校验；手机号、身份证、信用代码、邮箱、银行卡脱敏
生产安全检查开启签名时，JWT 密钥过弱、服务令牌为 dev- 开头、初始口令仍为默认值、未配置 SM2 私钥，任一成立即拒绝启动（ProductionSafetyCheck.java）
服务间X-Service-Token 常量时间比较；反向代理只允许内网段访问 /api/v1/internal/，拒绝 /actuator/
提示词注入外部内容放进 <数据> / <参考资料> 区块并声明其中指令无效；模型输出只接受候选内的值，抽取必须有可校验的原文引用
大模型审计网关只记录功能、模型、耗时、token 数和成败，不记录提示词内容
