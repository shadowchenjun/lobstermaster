01发布流程总览

不做后置分发层 —— 账号分配在生成阶段一次完成,产物直接落账号目录。

读账号配置
config/accounts.yaml → 5 个账号 id(纯分发槽位,无人设)。
算总量 & 反推每 BGM keep
总量 = 账号数 × --target-per-account;按 BGM 数均摊,keep 强制对齐到账号数整数倍。
每 BGM 出片 + round-robin 分配
候选生成 → LLM 编排 → fill_slots 兜底;选中的 N 条按 account_offset 错位轮转分到各账号。
直接归档到账号目录
渲染产物落 output/publish/<账号>/<日期>/,随片写 .publish.json(含 account_id / seed / 指纹)。
(可选)按账号补跑视觉扰动去重
--dedup 对每个账号目录单独跑,写到 <账号>_dedup/<日期>/。

02内部业务改动

commit cef9b78 + 6d232cd + 2dbf73b:从「单 BGM 出片到一个目录」升级为「整日跑批按账号分发」,并把远端 PG 主路径合回账号工作流。

A新增整日跑批入口 run_daily_batch

过去 beatmix mix 一次只跑一个 BGM、产物堆在 output/beatmix/<bgm_id>/,账号分配靠人工挑。现在新增 daily 子命令一条龙:

  • 输入「每账号目标条数」,自动遍历所有有 voicemap 的 BGM,反推每个 BGM 该出多少条。
  • 每个 BGM 内部仍走原有 run_beatmix(候选→LLM 编排→兜底→去重),只是末端多了账号分配与归档。
  • 返回 per_account 实际产出字典,日志逐条打印 plan seed=… → 账号=…。

B账号分配进入渲染层 _render_plans

渲染函数新增 account_assignments / publish_date / publish_output_dir 三个参数。每条 plan 渲染时:

# 有账号分配时,输出目录改为账号/日期层级
out_dir = publish_output_dir / account_id / publish_date
out_path = out_dir / f"{bgm_id}_{seed}_{fingerprint.D2}.mp4"

# 随片落盘的 publish_meta 注入 account_id
publish_meta["account_id"] = account_assignments[idx]

这样生成与归档合一,没有中间搬运脚本,产物天然带账号归属和 .publish.json 元数据。

C按账号去重 dedup_publish / dedup-publish 子命令

视觉扰动去重改为以账号目录为单位:源 publish/<账号>/<日期>/ → 目标 publish/<账号>_dedup/<日期>/。新增独立子命令,可对已出片的目录事后补跑,支持 --accounts 只处理指定账号。

DPostgreSQL 素材源并入账号工作流(6d232cd / 2dbf73b)

素材层从 SQLite 扩展到 PG:db_pg.py 补齐 query_materials / get_material / get_stats / curated_clips 增删查,并接入 runner 与 orchestrator,使账号跑批可直接以 PG 为素材源(--from-pg)。合并时保留本地账号分发主体,只把远端 PG 主路径和查询能力并入。

当前代码的数据源优先级是 PG > SQLite > tags.json:--from-pg 优先于 --from-db;SQLite 仍可作为本地兼容路径;没有 DB 参数时回落到素材目录里的 tags.json。

03执行策略(分配算法)

核心要解决两件事:① 总量怎么均摊到每个 BGM;② 怎么保证 5 个账号拿到的视频互不雷同。

3.1 每 BGM keep 的反推

目标:5 账号 × 10 条 = 50 条,均摊到所有 BGM,且每 BGM 的 keep 必须是账号数(5)的整数倍(否则账号分配不均)。

# total_needed = target_per_account × n_accounts
base_keep = (total_needed // n_bgms // n_accounts) * n_accounts   # 对齐到 5 的倍数
if base_keep == 0: base_keep = n_accounts                          # 至少每账号 1 条
k_extra   = (total_needed - base_keep * n_bgms) // n_accounts     # 前 k_extra 个 BGM 多跑一轮

# 例:50 条 / 4 个 BGM / 5 账号
#   base_keep = (50//4//5)*5 = 10;  k_extra = (50-10*4)//5 = 2
#   → 前 2 个 BGM 各 keep 15,后 2 个各 keep 10  →  合计 50

余数被摊给前 k_extra 个 BGM(每个多出一整轮 = 一组账号),保证总量精确且每账号均分。

3.2 账号错位轮转 account_offset

同一批内按 round-robin 分配;关键是每个 BGM 把轮转起点偏移 1,避免「账号A 永远拿每个 BGM 的第 0 条」这种系统性雷同:

# 每条 BGM 的 offset 递增
offset = bgm_idx % n_accounts
account = accounts[(i + offset) % n_accounts]   # 第 i 条视频归谁
错位前账号A 永远拿 seed 最小的那条 → 跨 BGM 风格趋同,平台易判定关联
→
错位后每个 BGM 起点 +1,各账号跨 BGM 拿到不同编号/不同素材编排的视频

3.3 硬约束与兜底

约束实现
同视频不跨账号一条 plan 只渲染一次、只归一个账号目录,sha 天然唯一
keep 非账号倍数日志 warning 提示并建议改成最近的整数倍,末尾账号会少一条
账号间均匀round-robin + offset,per_account 实时累计回执

04优化了哪些地方

跑批量级上来后,围绕画质、性能、稳定性的针对性优化。

画质
竖屏拉伸修复:scale 改 crop 保比例
scale={w}:{h} 直接拉伸会让横屏素材变形。改为 force_original_aspect_ratio=increase + crop,先按比例放大再居中裁切,画面不变形。
编码
硬件编码 h264_videotoolbox 替代 libx264
切到 macOS VideoToolbox 硬件编码,批量出片大幅提速、降 CPU 占用,适配 50 条/天的吞吐。
画质
竖屏素材过滤 is_portrait + PG 兼容列
SQLite materials 表已有 is_portrait 字段(按 ffprobe 宽高、含 rotate 元数据判定),load_all_materials 自动剔除横屏素材。PG schema 同步补 duration_sec / is_portrait 兼容列,让账号跑批与 PG 素材库共用同一套候选过滤逻辑。
稳定性
历史 plan 写入与 DB 读路径分离
SQLite 路径继续把已出片 plan 写回 mix_plans 供跨次去重;PG 路径聚焦素材读取和运营查询,渲染归档仍靠 .publish.json 保留账号、日期、seed 与指纹。
稳定性
渲染超时 180s → 600s(1ee74b0)
硬件编码长视频偶发超过 3 分钟被误杀,normalize / render_video 超时统一提到 10 分钟。
性能
只 probe 被选中的 opener
starter 池可能很大,改为只对实际入选的 opening_clip 做 ffprobe,跳过未使用的 starter,减少无谓 I/O。
整洁
清理废弃 voicemap
删除 bgm_drink_* / bgm_ds_05 / bgm_sample_01 等过期槽位表,新增 bgm_01.json 与 config/dedup/bgm03new.yaml(禁翻转)。

05命令与产物

新增 daily / dedup-publish 子命令,并让 mix / daily 支持 --from-pg。

# 整日跑批:5 账号 × 10 条,按账号分发归档
python -m src.orchestrator beatmix daily \
    --target-per-account 10 --accounts-config config/accounts.yaml \
    --publish-date 2026-06-29 --dedup --from-pg

# 兼容本地 SQLite 素材库路径
python -m src.orchestrator beatmix daily \
    --target-per-account 10 --accounts-config config/accounts.yaml \
    --publish-date 2026-06-29 --dedup --from-db

# 对已出片目录补跑视觉扰动去重(可只挑账号)
python -m src.orchestrator beatmix dedup-publish \
    --publish-date 2026-06-29 --accounts 账号A,账号B
