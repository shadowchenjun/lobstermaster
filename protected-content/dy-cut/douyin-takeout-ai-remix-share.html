项目背景概要

本项目服务于自营餐饮品牌的抖音本地生活内容生产。业务需要从每周约 100 分钟菜品特写素材中， 稳定批量生成 500-1000 条短视频，用于门店账号或投放人员手动上传抖音，视频内不嵌入店名、 POI、水印或团购角标，由平台在发布与投放链路中叠加。

15s目标成片时长，允许约 ±0.3s 漂移
1080×1920Phase 1 成片规格，9:16 竖屏，H.264 + AAC
5 模板T01-T05，对应不同节奏、钩子和调色策略
5-30当前推荐套餐库规模，扩到 100+ 需调差异化参数
7 维开场、顺序、BGM、转场、字幕、调色、节奏差异化
< ¥100/周Phase 1 成本控制目标，按批次成本日志持续核算

Phase 1 范围

类别内容说明
已纳入 素材导入、去重、抽帧、语义理解、文案生成、选片、混剪、导出、复审 覆盖从原始菜品特写素材到待审 MP4 的完整链路。
暂不做 抖音 OpenAPI 上传、多账号矩阵、SaaS 化、AI 配音、数据回传 这些能力留给 Phase 2/3，Phase 1 保持本地自营生产闭环。
产物定义 裸片 视频仅包含画面、字幕、调色、转场和 BGM，不包含平台水印和团购入口。

开发技术架构

系统采用三层架构：本地 Gradio 复审 UI、Python orchestrator 编排层、worker 执行层。耗算力的语义理解和文案生成走云 API， 视频媒体处理、缓存、差异化、导出和复审全部在本地完成。

交互层

Gradio 本地 Web，默认运行在 http://127.0.0.1:7860。用于逐条观看、查看套餐/模板/BGM、编辑字幕、记录重生成要求、通过或丢弃。

编排层

src/orchestrator.py 是主状态机，读取 settings、同步套餐、调度各 stage、统计成本并写日志。

执行层

ffmpeg/ffprobe、MiniMax-M3 VLM、MiniMax-M3 LLM、飞书 OpenAPI、BGM 选择、字体解析和缓存读写。

7 维差异化引擎

差异化不是简单去重，而是在同一套餐近期产物中主动制造变化。当前实现从候选空间采样 N=20 个方案， 与最近 K=10 条历史指纹对比，按权重选择差异分最高的方案。

VLM 与 LLM 能力整合

当前系统把 AI 能力拆成两类：VLM 负责“看懂素材”，LLM 负责“生成文案”。两者分别解决画面理解和批量话术生产问题， 再由 select 和 render 阶段把“合适的画面”与“合适的字幕”组合成可投放短视频。

VLM：素材语义理解

实现位置：src/stages/understand.py 与 src/workers/vlm_worker.py。 frame 阶段先抽关键帧，understand 阶段取前 3 张图调用MiniMax-M3 Vision，并要求模型返回严格 JSON。

  • 输入：单条 clip 的关键帧、VLM prompt、MiniMax-M3 API 配置。
  • 输出：ClipSemantics，落地到 scratch/features/<clip_id>.json。
  • 字段：主菜名、置信度、食材、动作、视觉风格、适合钩子、不适合钩子、理解时间。
  • 逻辑：图片转 base64，拼成多模态 chat/completions 请求，开启 JSON response format，失败指数退避重试。
  • 缓存：若语义文件存在且比原视频新，直接读取缓存，避免重复调用和重复扣费。
LLM：套餐字幕生成

实现位置：src/stages/copy.py 与 src/workers/llm_worker.py。 copy 阶段按 combo × template 预生成字幕，把套餐信息转成抖音短视频话术。

  • 输入：套餐名、价格、原始卖点、主食材、模板 ID、MiniMax-M3 API 配置。
  • 输出：SubtitlePlan，缓存到 cache/copy/<combo>_<template>.json。
  • 结构：1 句钩子、3 句卖点、1 句 CTA，每句提供多个候选。
  • 逻辑：拼接 prompt 和 JSON schema hint，调用 MiniMax-M3 JSON mode，解析为 5 条 SubtitleLine。
  • 兜底：LLM 调用失败或返回结构不完整时，使用 config/fallback_copy.json，并同样写入缓存。

AI 在流水线中的位置

能力发生阶段解决的问题后续如何使用
VLM frame → understand 把“视频文件”转成“可被程序理解的菜品语义”，避免盲目随机选片。 select 阶段可根据 hook_fit、动作标签和视觉风格挑选更匹配的片段。
LLM copy 把“套餐信息”转成“短视频字幕话术”，减少人工反复写文案。 render 阶段通过 ffmpeg drawtext 把字幕烧录到视频中。
缓存与兜底 understand / copy 控制云 API 成本，并避免 API 临时失败导致整批停摆。 重复跑批时优先读本地 JSON 缓存；LLM 不可用时使用 fallback 文案。

使用核心工具

Python 3.11

项目主语言。依赖通过 pyproject.toml 管理，主要包包括 PyYAML、loguru、httpx、Pillow、imagehash、Gradio、pytest。

ffmpeg / ffprobe

媒体处理硬依赖，用于 probe、抽帧、多段拼接、变速、转场、字幕烧录、混音和导出。字幕需要带 drawtext/libfreetype 的 ffmpeg-full。

MiniMax-M3 Vision

通过火山引擎 OpenAI-compatible chat completions 接口理解关键帧，输出菜品名、食材、动作、视觉风格和适合钩子。

MiniMax-M3

用于生成套餐专属字幕文案。输出 1 句钩子、3 句卖点、1 句 CTA，每句多个候选，并缓存到本地。

Gradio

提供本地复审工作台，供运营人员快速看片、查看 combo/template/BGM 详情、编辑字幕、记录重生成 prompt、通过或丢弃。复审状态直接回写 manifest。

飞书 OpenAPI

可选套餐库来源。四个飞书环境变量完整时拉取多维表格，否则自动降级到本地 JSON。

使用说明

常规使用分为安装依赖、配置 API key、准备素材和 BGM、跑批、复审五步。下面命令以项目根目录为工作目录。

1. 安装依赖

brew install ffmpeg-full
pip install -e ".[dev]"
python -m src.orchestrator --version

2. 配置环境变量

cp .env.example .env
# 编辑 .env，填写：
# DOUBAO_API_KEY / DOUBAO_MODEL / DOUBAO_BASE_URL
# DEEPSEEK_API_KEY / DEEPSEEK_MODEL / DEEPSEEK_BASE_URL
# FEISHU_APP_ID / FEISHU_APP_SECRET / FEISHU_BITABLE_APP_TOKEN / FEISHU_BITABLE_TABLE_ID 可选

3. 准备素材与 BGM

mkdir -p input/raw/2026-06-09
cp /你的素材/* input/raw/2026-06-09/

mkdir -p cache/bgm
# 放入 bgm_01.m4a 等文件，并维护 cache/bgm/bgm_index.json
当前版本输入目录固定为 input/raw/2026-06-09/；--week 只用于成本报告命名， 暂不改变素材扫描目录。源素材支持 MP4/MOV/M4V，系统会自动转成 1080×1920 proxy。

4. 跑一批

LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8 zsh -lc 'set -a; source .env; set +a; .venv/bin/python -m src.orchestrator run --week 2026-W24'

logs/

5. 启动复审工作台

调参配置

项目把可调参数集中在 YAML 和 JSON 中。一般节奏、色彩、字幕大小、BGM 池和差异化策略都不需要改代码。

文件调整内容典型场景
config/settings.yaml 输出时长、分辨率、fps、码率、成本阈值、并发、差异化 K/N/权重。 调整产物规格、成本报警或套餐规模扩大。
config/templates/T01_*.yaml 至 T05_*.yaml 切片时长、转场池、字幕位置/颜色/描边/字号、调色、BGM 池。 字幕太大、节奏太慢、色彩偏暗、BGM 不合适。
catalog/combos.json 套餐 ID、名称、价格、卖点、主食材、上下架状态。 没有接飞书时手工维护套餐库。
cache/bgm/bgm_index.json BGM id、pool、bpm、时长、文件路径、来源和授权说明。 新增或替换抖音可用 BGM。
config/fallback_copy.json LLM 不可用时的兜底字幕。 API 异常或离线测试。

模板定位

模板名称定位
T01极速食欲冲击默认主力模板，0.6-1.0s 快切，暖橘高饱和。
T02慢镜特写强调关键镜头慢放，突出拉丝、爆浆、油亮质感。

T04价格钩子前置前 2 秒价格强钩子，适合入门套餐。
T05套餐豪华感强调 99 元或多人套餐价值感。

已知限制与建议下一步

当前限制
  • 输入素材目录仍固定为 input/raw/2026-06-09/。
  • M1 8GB 不适合跑 7B+ 本地模型，VLM/LLM 依赖云 API。
  • 缺少 cache/bgm/bgm_index.json 时渲染阶段会跳过。
  • 字幕烧录依赖带 drawtext 的 ffmpeg-full。
  • 套餐规模扩到 100+ 时，差异化历史窗口和候选采样需要重新调优。
  • 复审界面已能记录修改和重生成要求，但单条即时重渲染消费器仍需补齐。
建议下一步
  • 把输入目录从固定日期改为按 --week 或显式 --input-dir 推导。
  • 补齐重生成队列消费器，让复审工作台提交的字幕、prompt、Template 和 BGM 修改能直接生成新版视频。
  • 为 BGM index 增加校验命令，提前发现路径缺失或模板池为空。
  • 对接真实飞书表字段映射文档，减少套餐库维护歧义。
  • 补一条“无真实 API 的本地 demo 跑批”命令，方便新机器验收。
