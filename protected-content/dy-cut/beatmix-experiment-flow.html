Phase 1 实验链路 · beatmix · 更新于 2026-06-14

口播 BGM 卡点混剪实验流程说明

新方案把传统“素材填满时长、BGM 贴上去”的做法反过来： 先把口播 BGM 拆成带时间的内容槽位，再让素材逐槽卡点。 目标是在餐饮外卖短视频里实现“念到猪排就看见猪排，念到配送就看见包装/出餐”的声画同步。

当前实现状态

3子命令已上线：beatmix tag / score / mix
6差异化 fingerprint 维度，控制同 BGM 多条视频不撞
1080×1920默认 9:16 满屏输出，--workers 并行渲染
A–X素材质量分级淘汰：src/beatmix/quality.py
方案变化 输入资产 运行流程 代码映射 现状与缺口 协作交接
01 · Strategy

核心变化：BGM 不是背景，是剪辑骨架

老流程追求批量产出和差异化，新实验追求“口播语义和画面素材对齐”。两条链路隔离，互不影响。

旧 run 流程

选片填时长，BGM 叠加

先按 hook、差异化和模板节奏挑选素材片段，填满 15 秒；BGM 只作为音轨叠上去，不理解歌词/口播内容。

适合：稳定批量跑 5 套餐 × 5 模板，产出可复审的视频池。

新 beatmix 实验

先读口播槽位，再让素材卡点

先把口播 BGM 转成带时间戳的 voicemap，再让正文素材按菜名、价格、包装、配送等槽位逐段匹配。

适合：验证专业剪辑打法，追求强钩子开头和声画同步。

02 · Assets

实验输入资产全部独立存放

这些目录与老流程 input/raw、scratch/features 隔离。协作者只要补齐这几类资产，就能跑 beatmix。

路径 内容 谁产生 / 谁维护 当前代码状态
input/starter/ 黄金开头素材，通常是端菜、近景、强食欲钩子，默认取约 2 秒。 人工挑选放入；无需标签。 已读取，runner.py 用随机种子选择。
input/material/ 正文卡点素材，文件名必须能被 tags.json 引用。 人工放入，后续可接素材库。 已读取素材时长，用于中心裁剪。
input/material/tags.json 每条正文素材的 category、dish、is_bspot。 由 VLM 自动初标 + 人工校正,并含 quality(A–X 评分)。 beatmix tag 生成、beatmix score 补 quality;出片时按 use_policy 取舍。
config/bgm_voicemap/<bgm_id>.json BGM 口播槽位表：时间、文字、kind。 ASR 离线转写 + LLM 初分 kind + 人工校正。 已读取；asr.py 有离线生成能力，但未挂 CLI。
cache/bgm/bgm_index.json BGM id 到真实音频路径的索引。 人工维护或由导入工具维护。 已读取；--bgm 必须能在这里找到。 
{
  "mat_001.mp4": {"category": "主菜", "dish": "烤猪排", "is_bspot": false},
  "mat_002.mp4": {"category": "烤串", "dish": "烤串", "is_bspot": false},
  "mat_003.mp4": {"category": "价格牌", "dish": "", "is_bspot": false},
  "mat_004.mp4": {"category": "空镜", "dish": "", "is_bspot": true}
}
字段解释

tags.json 怎么理解

category 是粗分类，决定 fallback 的素材池；dish 是细菜名，帮助 LLM 语义匹配；is_bspot 表示万能补位镜头，可用于包装、配送、价格、空镜等 filler 槽位。

03 · Pipeline

一条 beatmix 视频如何生成

当前实现是“读输入 → LLM 编排 → 代码兜底 → 去重筛选 → 转成 SegmentPlan → ffmpeg 渲染”。

1读取 BGM 槽位从 config/bgm_voicemap/<bgm_id>.json 读取口播时间轴，过滤掉 intro。
2读取素材标签读取 input/material/tags.json，把素材变成可被 LLM 选择的清单。
3LLM 一次编排把所有槽位和所有素材一次性发给 LLM，返回 slot_idx 到 clip 的映射。
4确定性兜底LLM 选错、重复或缺失时，按菜品/空镜/万能素材补齐，避免黑屏。
5差异化去重采样 30 个候选，按 D1-D6 fingerprint 选出不撞的 Top-N。
6渲染输出转成现有 SegmentPlan，复用 render + ffmpeg，输出 mp4 和 plan.json。
关键业务判断：开头素材是“黄金 2 秒豁免区”，不参与口播语义匹配；后续正文素材才严格按口播槽位时长卡点。
04 · Code Map

代码如何对应方案

以下是协作者最需要看的文件。先看入口和 runner，再看四个纯函数模块。

src/orchestrator.py
注册 beatmix tag / score / mix 三个子命令(及兼容旧 --bgm)。mix 调 run_beatmix(args.bgm, settings, n_keep, material_dir, workers)。
src/beatmix/runner.py
实验流程主编排：读取 voicemap、materials、starter；构建 LLM prompt；采样候选；去重；探测素材时长；渲染；写 .plan.json。
src/beatmix/asr.py
口播 BGM 的离线转写工具：ASR 得到词/短句时间戳，再用 LLM 给短句标 intro、dish、filler，最终形成 voicemap。
src/beatmix/materials.py
读取 input/material/<week>/tags.json(含 category/dish/quality),供编排链路使用。质量评分逻辑在 src/beatmix/quality.py。
src/beatmix/tagging.py
素材 VLM 自动打标模块：扫描 input/material 下的视频，抽取若干帧，调用注入的 VLM 函数生成 category、dish、is_bspot，写入 tags.json；已存在的素材标签会跳过，保留人工校正。
src/beatmix/assembler.py
槽位填充与兜底：LLM 选择有效则采用；无效则按 food/filler 类别、is_bspot、任意未用素材逐层兜底。
src/beatmix/dedup.py
D1-D6 指纹和去重。硬约束确保整体序列和菜品序列不重复，软距离控制开头、集合、filler、类别首选差异。
src/beatmix/render_adapter.py
把 BeatMixPlan 转成老渲染器能吃的 SegmentPlan。每个正文素材按槽位时长做中心裁剪。
# 1) 素材 VLM 打标 → tags.json
python -m src.orchestrator beatmix tag   --dir input/material/2026-W24
# 2) 素材质量评分(A–X,写回 tags.json + 报告)
python -m src.orchestrator beatmix score --dir input/material/2026-W24 --workers 4
# 3) 出片(默认 1080×1920,并行渲染)
python -m src.orchestrator beatmix mix   --bgm bgm_core_01 --keep 10 \
    --material-dir input/material/2026-W24 --workers 4
# 兼容旧用法:python -m src.orchestrator beatmix --bgm bgm_core_01 --keep 10

# 输出
output/beatmix/<bgm_id>/
  <bgm_id>_<variant_seed>_<fingerprint>.mp4
  <bgm_id>_<variant_seed>_<fingerprint>.plan.json  # 卡点明细 + fingerprint
05 · Reality Check

当前已实现与尚未接上的部分

这部分适合汇报时直接说明，避免把设计目标误认为已完成能力。

已实现

beatmix 主链路 + 声画同步

命令入口、voicemap 读取、LLM 编排(每槽 3–5 候选)、fallback、去重、SegmentPlan 适配、并行渲染都已接入。render_adapter 按完整 voicemap 平铺,「输出时间轴 == BGM 时间轴」,修复了开头 prepend 导致的整体偏移。

已命令化

素材 VLM 打标 + 质量评分

beatmix tag 扫描/抽帧/VLM 打标写 tags.json;beatmix score(src/beatmix/quality.py)给素材 A–X 分级与 use_policy,出片时高分优先、X 档淘汰。均有单测。

半命令化

ASR 生成 voicemap

src/beatmix/asr.py 的 DashScope paraformer 转写 + 词级时间戳聚合 + LLM 标 kind 已可用,但**仍走一次性脚本**(无 voicemap 子命令)。产物人工校正后入库。

下一步可选迭代:把 transcribe_to_voicemap 也注册为 beatmix voicemap --bgm xxx --audio xxx,让两个离线准备步骤(voicemap / tag+score)全部命令化;以及在 fill_slots 给 dish 槽位引入候选随机,突破「dish 固定→同 BGM 只产 1 条」的去重瓶颈。
06 · Handoff

给协作者的最短上手路径

如果只想跑通一次实验，按下面顺序准备即可。

运行前检查

  • cache/bgm/bgm_index.json 中存在目标 bgm_id。
  • config/bgm_voicemap/<bgm_id>.json 已人工校正时间和文字。
  • input/starter/ 至少有 1 条 mp4，最好 10 条以上。
  • input/material/<week>/ 有正文素材;先 beatmix tag 再 beatmix score 生成 tags.json(含 quality)。
  • .env 的 MiniMax(LLM/VLM)与 DashScope(ASR)key 可用;uv pip install -e ".[asr]"。

验收标准

  • 输出目录有 mp4 和对应 .plan.json。
  • 口播念到菜品时，画面主体是对应菜品或近似类目。
  • 价格、包装、配送类口播不黑屏，能用价格牌/空镜/出餐动作承接。
  • 同一 BGM 的多条成片不出现完全相同的正文素材序列。
  • 素材不足时允许少产，但不为了凑数放宽硬约束。
