Phase 1 实验链路 · beatmix · 更新于 2026-06-20

口播 BGM 卡点混剪实验流程说明

新方案把传统“素材填满时长、BGM 贴上去”的做法反过来： 先把口播 BGM 拆成带时间的内容槽位，再让素材逐槽卡点。 目标是在餐饮外卖短视频里实现“念到猪排就看见猪排，念到配送就看见包装/出餐”的声画同步。

当前实现状态

6子命令已上线：tag / score / mix / db-sync / prepare / asr
1,097条素材已入本地 SQLite 库，跨 5 个 batch；--from-db 一键全量加载
6 层视觉扰动去重：scale · crop · 亮度对比度 · 翻转 · 旋转 · PiP（--dedup）
A–X素材质量分级；B+C 级 775 条默认可用，D 级可人工升档
方案变化 输入资产 素材 DB 运行流程 视觉去重 代码映射 现状与缺口 协作交接
01 · Strategy

核心变化：BGM 不是背景，是剪辑骨架

老流程追求批量产出和差异化，新实验追求“口播语义和画面素材对齐”。两条链路隔离，互不影响。

旧 run 流程

选片填时长，BGM 叠加

先按 hook、差异化和模板节奏挑选素材片段，填满 15 秒；BGM 只作为音轨叠上去，不理解歌词/口播内容。

适合：稳定批量跑 5 套餐 × 5 模板，产出可复审的视频池。

新 beatmix 实验

先读口播槽位，再让素材卡点

先把口播 BGM 转成带时间戳的 voicemap，再让正文素材按菜名、价格、包装、配送等槽位逐段匹配。

适合：验证专业剪辑打法，追求强钩子开头和声画同步。

02 · Assets

实验输入资产全部独立存放

这些目录与老流程 input/raw、scratch/features 隔离。协作者只要补齐这几类资产，就能跑 beatmix。

路径 内容 谁产生 / 谁维护 当前代码状态
input/starter/ 黄金开头素材，通常是端菜、近景、强食欲钩子，默认取约 2 秒。 人工挑选放入；无需标签。 已读取，runner.py 用随机种子选择。
input/begin/ 新批次开头素材（门头、环境、强钩子），与 starter/ 合并后扩大开头池。 人工放入；无需标签。 合并到 input/starter_all/ 通过软链使用。
input/starter_all/ input/begin/ + input/starter/ 合并目录（软链），当前共 28 条开头素材。 执行 mkdir -p input/starter_all && ln -sfn … 一次性建立。 --starter-dir input/starter_all/ 指定使用；推荐固定用此目录。
input/material/<week>/ 正文卡点素材（按周分目录）。可软链到原始素材：ln -sfn raw/2026-W24 input/material/2026-W24。 人工放入，后续通过 beatmix prepare 全流水线处理。 通过 beatmix tag / score / db-sync 逐步入库；--from-db 模式下不再直接读取。
input/material/<week>/tags.json 每条正文素材的 category、dish、is_bspot 及 quality(A–X 评分)。 由 VLM 自动初标 + 人工校正。 beatmix tag 生成、beatmix score 补 quality；beatmix db-sync 同步到 SQLite。
cache/material_library.db SQLite 素材库，跨全部 batch 聚合。字段含 file_path（绝对路径）、category、use_policy、tier 等。 由 beatmix db-sync --dir … 写入；--from-db 出片时读取。 当前已入库 1,097 条（5 个 batch）；B+C 级 775 条默认可用；D/X 级排除。
config/bgm_voicemap/<bgm_id>.json BGM 口播槽位表：时间、文字、kind。 ASR 离线转写 + LLM 初分 kind + 人工校正。 已读取；beatmix asr CLI 已上线。
cache/bgm/bgm_index.json BGM id 到真实音频路径的索引。 人工维护或由导入工具维护。 已读取；--bgm 必须能在这里找到。
input/pip/ PiP 叠加素材（低透明度覆盖层，用于视觉去重）。 人工放入，建议放 2–5 条店铺/Logo 短片。 当前为空，--dedup 时自动降级为纯视觉扰动（不报错）。

字段解释

tags.json 怎么理解

category 是粗分类，决定 fallback 的素材池；dish 是细菜名，帮助 LLM 语义匹配；is_bspot 表示万能补位镜头，可用于包装、配送、价格、空镜等 filler 槽位。

02b · Material DB

use_policy 分级： preferred（A 级）→ 最优先；normal（B 级）→ 默认可用；fallback（C 级）→ 含 --from-db 时一并加载；review（D 级）→ 待人工复审，出片时排除；reject（X 级）→ 永久淘汰。 D 级素材可在 tags.json 手动改 use_policy 后重新 db-sync 升档。
03 · Pipeline

一条 beatmix 视频如何生成

完整链路：读槽位 → 加载素材（db 或 tags.json）→ LLM 编排 → 兜底 → fingerprint 去重 → 渲染 → 视觉扰动（可选）。

1读取 BGM 槽位从 bgm_voicemap/<bgm_id>.json 读取口播时间轴，过滤掉 intro。
2加载素材--from-db：从 SQLite 跨 batch 加载 775 条（B+C 级）
默认：读单周 tags.json。
3LLM 一次编排把所有槽位和素材清单一次性发给 LLM，返回每槽 3–5 候选 + score。
4确定性兜底LLM 选错/重复/缺失时，按菜品 → 空镜 → 万能素材逐层补齐，绝不黑屏。
5fingerprint 去重采样 30 候选，D2（全序列）+ D4（主菜序列）不撞历史，选 Top-N。
6渲染输出转成 SegmentPlan，ffmpeg 输出 mp4 + plan.json（含卡点明细）。
7视觉扰动
--dedup6 层 ffmpeg 滤镜改变平台视觉指纹，输出到 <bgm_id>-dedup/。
关键业务判断：开头素材（input/starter_all/）是”黄金 2 秒豁免区”，不参与口播语义匹配，由随机种子从开头池随机取；后续正文素材严格按口播槽位时长卡点。
03b · Visual Dedup

视觉扰动去重：改变平台视觉指纹

--dedup 对产出的 mp4 做单次 ffmpeg 处理，6 层扰动叠加，参数由文件名 hash 确定性生成——同一文件每次结果一致，不同账号传不同 visual_seed 可得到差异版本。

扰动层参数范围（默认）作用状态
scale 放大×1.01 ~ ×1.02轻微放大，改变像素位置分布✅ 已启用
crop 微裁剪1% ~ 3%放大后裁回原分辨率，改变边缘像素✅ 已启用
亮度 / 对比度brightness ±5，contrast 0.95–1.05整体色调微调，改变色彩指纹✅ 已启用
水平翻转50% 概率（需 allow_flip=True）镜像画面，彻底改变构图指纹✅ 已启用
旋转1° ~ 2°，可为负值轻微旋转后 scale 归位，改变帧对齐✅ 已启用
PiP 叠加opacity 2%，volume 2%低透明度覆盖另一视频，改变深层特征⚠️ 降级：input/pip/ 暂无素材
 
# 出片同时生成去重版（推荐）
python -m src.orchestrator beatmix mix \
    --bgm bgm_core_01 --keep 10 \
    --starter-dir input/starter_all/ \
    --from-db --workers 4 --dedup

# 产物结构：
output/beatmix/bgm_core_01/          ← 10 条原版
output/beatmix/bgm_core_01-dedup/    ← 对目录内所有 mp4 去重

# 不同账号传不同 visual_seed（在 config/dedup/video_dedup.yaml 配置）：
# processing:
#   visual_seed: 1    ← 账号 B
#   visual_seed: 2    ← 账号 C
去重产物数量说明

为什么去重版比原版多？

--dedup 扫描的是整个 <bgm_id>/ 目录（含历史原版），而非只有本次新产的 10 条。首次运行会对所有已有原版补生成去重版；后续重复运行时，已有去重版会被跳过（overwrite: false）。

如需多个 seed 变体（如 10 条原版 × 3 seed = 30 条去重版），可传不同 visual_seed 分批运行到不同子目录。

04 · Code Map

代码如何对应方案

以下是协作者最需要看的文件。先看入口和 runner，再看四个纯函数模块。

src/orchestrator.py
注册 beatmix tag / score / mix / db-sync / prepare / asr / viscluster 七个子命令。mix 新增 --from-db（SQLite 素材库模式）和 --dedup（视觉扰动）参数。
src/beatmix/runner.py
实验流程主编排。新增 db_path 参数：不为 None 时调 load_all_materials(db_path) 取跨 batch 素材，用 clip_path_map（绝对路径字典）定位源文件；同时透传给 _render_plans → to_segment_plan。dedup=True 时在渲染完成后调 _dedup_outputs。
src/beatmix/db.py
SQLite 素材库存储层（单张宽表 materials）。sync_from_tags 把 tags.json 批量 upsert；load_materials(batch) 读单批次；load_all_materials(db_path) 跨全部 batch 加载，返回 (list[MaterialTag], clip_path_map)，include_review=False 时排除 D/X 级。
src/beatmix/video_processor.py
视觉扰动去重核心。DedupeTemplate 定义 6 层扰动参数（YAML 驱动）；build_visual_params 用文件名 hash 确定性生成参数；build_video_filter 组装 ffmpeg vf 字符串；process_video 单次 ffmpeg 调用完成编码；load_dedup_template 读 config/dedup/video_dedup.yaml（可按 bgm_id 覆盖）。
src/beatmix/render_adapter.py
把 BeatMixPlan 转成 SegmentPlan。新增 clip_path_map 参数：非 intro 槽优先用 map 里的绝对路径作为 clip_id，从而在 --from-db 模式下无需 material_dir。
src/beatmix/asr.py
口播 BGM 离线转写：DashScope paraformer 词级时间戳 → LLM 标 intro/dish/filler → voicemap JSON。
src/beatmix/materials.py
读取 tags.json（单周模式），供非 db 模式使用。质量评分在 src/beatmix/quality.py；is_usable(m, include_fallback=True) 控制 C 级是否可用。
src/beatmix/assembler.py
槽位填充与兜底：LLM Top-K 带权采样 → 按类别/is_bspot/duplicate_group 逐层降级，始终绝不空槽。
src/beatmix/dedup.py
D1-D6 fingerprint 去重（内容层）：D2 全序列 + D4 主菜序列硬约束，确保同 BGM 多条视频不撞。与 video_processor.py 的视觉去重互补：前者是内容不重复，后者是视觉指纹不重复。

05 · Reality Check

当前已实现与尚未接上的部分

这部分适合汇报时直接说明，避免把设计目标误认为已完成能力。

已实现

beatmix 主链路 + 声画同步

命令入口、voicemap 读取、LLM 编排(每槽 3–5 候选)、fallback、去重、SegmentPlan 适配、并行渲染。render_adapter 按完整 voicemap 平铺,「输出时间轴 == BGM 时间轴」。

已实现

SQLite 素材库 + --from-db

beatmix db-sync 把 tags.json 批量 upsert 到 cache/material_library.db；beatmix prepare 一键全流水线（tag→score→viscluster→db-sync）；mix --from-db 跨 5 个 batch 加载 775 条 B+C 级素材，file_path 绝对路径定位源文件，不依赖 material_dir。

已实现

视觉扰动去重 --dedup

6 层 ffmpeg 滤镜（scale/crop/eq/hflip/rotate/PiP），参数由文件名 hash 确定性生成。visual_seed 支持多账号差异化。当前 PiP 降级（input/pip/ 为空）；放入视频素材后自动激活。

已命令化

素材 VLM 打标 + 质量评分

beatmix tag 扫描/抽帧/VLM 打标写 tags.json；beatmix score 给素材 A–X 分级与 use_policy，出片时高分优先、X 档淘汰。均有单测。

已命令化

ASR 生成 voicemap

beatmix asr CLI 已上线：DashScope paraformer 转写 + 词级时间戳聚合 + LLM 标 intro/dish/filler，产出 voicemap JSON，人工校正后入库。

待完善

PiP 去重层 + 多变体出片

PiP 叠加因 input/pip/ 空而降级，放入 2–5 条店铺短片即可激活。
多 seed 变体（10 条 × N seed = N×10 条去重版）目前需手动多次传不同 visual_seed；可新增 --dedup-variants N 参数一次完成。

下一步可选迭代：① input/pip/ 放入店铺/Logo 短片，激活 PiP 第 6 层扰动；② 新增 --dedup-variants N 参数，一次对每条原版产 N 个 seed 变体（10 原版 × 3 = 30 去重版）；③ D 级素材人工复审升档后 db-sync --force 写回，扩充可用素材池。
06 · Handoff

给协作者的最短上手路径

如果只想跑通一次实验，按下面顺序准备即可。

运行前检查

  • cache/bgm/bgm_index.json 中存在目标 bgm_id。
  • config/bgm_voicemap/<bgm_id>.json 已人工校正时间和文字。
  • input/starter_all/ 已建立（合并 begin/ + starter/），至少 10 条 mp4。
  • 素材已入库：beatmix prepare --dir input/material/<week>（或单步 tag → score → db-sync）。
  • cache/material_library.db 存在（--from-db 必需）；可用 sqlite3 cache/material_library.db "select batch,count(*) from materials group by batch" 检查。
  • .env 的 MiniMax(LLM/VLM)与 DashScope(ASR) key 可用；uv pip install -e ".[asr]"。

验收标准

  • 输出目录有 mp4 和对应 .plan.json。
  • 口播念到菜品时，画面主体是对应菜品或近似类目。
  • 价格、包装、配送类口播不黑屏，能用价格牌/空镜/出餐动作承接。
  • 同一 BGM 的多条成片不出现完全相同的正文素材序列（fingerprint D2/D4 互不撞）。
  • --dedup 产物在 <bgm_id>-dedup/ 目录，每条原版对应一条视觉扰动版。
  • 素材不足时允许少产，但不为了凑数放宽硬约束。
