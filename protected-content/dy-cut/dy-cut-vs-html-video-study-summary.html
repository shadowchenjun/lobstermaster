产品学习总结 · 2026-06-13

dy-cut vs html-video：谁负责让人馋，谁负责让信息更炸

这份总结把 dy-cut 和 nexu-io/html-video 放在同一个业务问题里看：抖音餐饮外卖视频批量生产。结论不是二选一，而是主链路和动效层的分工。

dy-cut 真实菜品素材混剪流水线，面向抖音外卖投流和自营批量生产。
html-video HTML/CSS 动画生成 MP4 的 agent 视频工具，适合图文动效和信息包装。
融合方向 dy-cut 做主体快剪，html-video 做价格牌、片头、CTA、榜单等 overlay 资产。
核心结论 功能对比 相同点 关键差异 适配场景 融合方案 落地建议 资料来源

一、核心结论

dy-cut 和 html-video 都能生成 MP4，但它们不是同类产品。dy-cut 的核心价值是从真实菜品素材中选片、混剪、差异化出片；html-video 的核心价值是把结构化内容和 prompt 转成 HTML 动画视频。

dy-cut 负责真实食欲和投流主链路，
html-video 适合成为动效包装供应商。

对餐饮外卖视频来说，最关键的是油亮、热气、拉丝、出锅、包装、数量感和市井真实感。这些必须来自真实素材。HTML 动画可以增强价格信息和转化信息，但不能替代菜品画面。

不要替代 不要用 html-video 替代 dy-cut 的选片、混剪、VLM 理解和 7 维差异化。
可以吸收 吸收 html-video 的 HTML 动效模板、agent 生成 storyboard、片头片尾和价格卡思想。

二、功能对比

下表按产品定位、输入输出、AI 使用方式、视频能力和业务适配做横向对比。

维度 dy-cut html-video
产品定位 抖音餐饮外卖视频 AI 混剪系统。 HTML/CSS 到 MP4 的 agent 视频生成工具。
目标用户 自营餐饮品牌、加盟店体系、外卖投流团队。 开发者、内容团队、AI agent 用户。
核心输入 菜品实拍视频、套餐库、授权 BGM、模板配置。 prompt、文章链接、GitHub repo、HTML 模板和结构化变量。
核心输出 15s 左右的 1080×1920 抖音竖屏裸片，人工复审后手动上传。 HTML 动画渲染出的 MP4，可用于解释视频、产品介绍、标题卡、数据视频。
视频主体 真实菜品特写、出餐、包装、桌面、炭火、热气。 HTML/CSS/GSAP/图文组件/数据图/标题动效。
AI 作用 VLM 看懂素材；LLM 生成抖音风格字幕文案；选片算法做差异化。 Agent 生成 storyboard、content graph、HTML frame 和模板变量。
渲染方式 Python orchestrator 调 ffmpeg 拼接、变速、调色、烧字幕、混 BGM。 Headless Chromium 录制 HTML 动画，再由 ffmpeg 编码 MP4。
模板体系 5 个餐饮外卖模板：极速食欲、慢镜特写、出锅过程、价格钩子、套餐豪华感。 23 个本地模板：数据图、glitch title、kinetic type、product promo、logo outro 等。
差异化机制 7 维指纹：开场镜头、镜头顺序、BGM、转场、字幕句、调色、节奏曲线。 主要靠模板选择、agent 生成内容、frame 顺序和视觉样式变化。
复审方式 Gradio 本地复审台：通过、丢弃、重生成。 本地 Studio：模板画廊、项目编辑、agent 生成、预览与导出。
平台适配 明确服务抖音餐饮外卖，输出裸片，平台自动加水印/团购入口。 通用视频生成工具，不专门适配抖音餐饮投流规则。
成熟度判断 自研垂直 MVP，需求边界清晰，适合继续围绕业务打磨。 开源早期项目，本地已可安装、构建、doctor 和 smoke 均通过。

三、相同点

都本地出片

两者最终都在本机生成 MP4，核心链路不依赖云端渲染服务，成本和隐私更可控。

都依赖 ffmpeg

dy-cut 用 ffmpeg 做拼接、字幕、调色和音频；html-video 用 ffmpeg 把录制结果编码为 MP4。

都有模板思想

dy-cut 的模板是餐饮视频节奏规则；html-video 的模板是可被 agent 填充的 HTML 动画框架。

都追求批量化

dy-cut 面向每周 500-1000 条；html-video 面向从 prompt/link/repo 自动生成多帧视频。

都不适合自由剪辑

它们都不是 PR/AE/剪映式时间线编辑器，而是通过规则和模板生成视频。

都适合 AI 介入

dy-cut 让 AI 看懂真实素材和写文案；html-video 让 agent 直接生产 storyboard 和 HTML frame。

四、最大不同：真实镜头 vs 信息动效

餐饮外卖视频的转化关键，不是“有没有动画”，而是“用户看了会不会馋、会不会觉得划算、会不会立刻想点”。这决定了 dy-cut 必须是主链路。

dy-cut

真实素材食欲钩子投流裸片

  • 从菜品实拍素材中挑选最有食欲的镜头。
  • 把热气、油光、拉丝、出锅、包装、数量感剪成短视频。
  • 用 7 维差异化解决批量出片的同质化问题。
  • 更适合作为抖音餐饮外卖视频的生产主干。
互补

html-video

HTML 动画信息包装Agent 生成

  • 把结构化内容变成标题卡、数据图、价格牌和 CTA。
  • 适合生成片头、片尾、榜单、促销卡、说明页。
  • 能用 agent 快速改文字、样式、分镜和模板变量。
  • 更适合作为 dy-cut 的动效层和素材补充层。

五、适配场景判断

dy-cut 更适合

  • 餐饮外卖真实素材混剪。
  • 多门店、多套餐、批量投流视频。
  • 菜品特写、出餐、包装、桌面氛围的快剪。
  • 需要同一套餐多条视频显著不同。
  • 需要复审、断点续跑和低成本周产。

html-video 更适合

  • 促销片头和片尾 CTA。
  • 价格牌、卖点条、限时优惠卡。
  • 本周热卖榜、套餐销量榜、门店战报。
  • 文章、项目、报告类内容解读视频。
  • 无需真实菜品画面的信息型视频。

重要边界

如果目标是“让用户看到菜马上想下单”，html-video 不能替代真实素材；如果目标是“把活动信息讲清楚、做得更有冲击力”，html-video 很有参考价值。

六、推荐融合方案

最合理的融合方式是：dy-cut 继续保持真实素材混剪主链路，html-video 的思想进入 dy-cut 的 motion_overlays 层。

1 真实素材输入 商家拍摄菜品、出餐、包装、门店和桌面场景。
2 dy-cut 选片 VLM 理解素材，select 阶段做镜头组合和差异化。
3 html 动效资产 生成价格牌、开场大字、卖点条、CTA 卡。
4 ffmpeg 合成 真实视频主体 + overlay + 字幕 + BGM 统一出片。
5 复审与投放 Gradio 通过/丢弃/重生成，合格裸片手动上传抖音。

短期可做

先不接完整 html-video，只借鉴它的模板思想，在 dy-cut 里实现确定性的价格牌、CTA 卡和开头冲击字。

中期可接

把 HTML 动效渲染成透明 WebM 或 PNG 序列，作为 dy-cut 的 overlay 资产进入 render 阶段。

长期可扩

做一个“自然语言改版助手”：用户说“开头更炸、价格晚点出”，系统转成可审计的模板 patch。

七、对 dy-cut 的落地建议

优先级 建议能力 说明 参考 html-video 的点
P0 motion_overlays 契约 在模板 YAML 中登记开场大字、价格牌、卖点条、CTA 卡的时间、位置、样式。 模板 manifest 和结构化变量。
P0 确定性价格牌 先用 ffmpeg drawtext/shape 实现，不依赖复杂 AI 动效，保证可测试可复现。 把信息块资产化，而不是逐条手工设计。
P1 HTML 片头/片尾生成器 用 HTML/CSS 生成 0-1.2s 开场和 13-15s 结尾 CTA，再合入 dy-cut 成片。 Chromium + ffmpeg 的 HTML 动画渲染方式。
P1 自然语言调参 复审时输入“少闪白、字幕更大、价格晚一点”，转成白名单 JSON/YAML patch。 agent 把人话转结构化改版请求。
P2 榜单/战报视频 用 html-video 思路生成“本周热卖 TOP5”“套餐复购榜”等非真实菜品主体视频。 数据图、rollup、kinetic type 模板。

不建议做的事

不要把主剪辑交给 html-video

餐饮主视频的核心是镜头本身，HTML 动画不能替代食物的真实质感。

不要变成自由时间线编辑器

dy-cut 的优势是批量、稳定、低成本、可复现。自由拖拽编辑会拖慢生产链路。
