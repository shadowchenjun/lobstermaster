dy-cut 团队导览: 抖音餐饮外卖视频 AI 混剪系统

这份介绍面向新加入项目的同学和需要协作拍摄、调参、复审的团队成员。它把当前版本的核心流程、最近两天的探索方向、素材质量最佳实践和后续深入方向放到一张地图里。

Phase 1 自营 9:16 短视频 模板批量线 口播 BGM 卡点 素材质量预处理

一句话理解项目

dy-cut 的目标是把餐饮门店素材,批量剪成适合抖音外卖转化的短视频。老主线解决“每周大量稳定出片”,新 beatmix 线解决“口播 BGM 声画同步更像专业剪辑”,质量预处理线解决“别让差素材拖累算法”。

原始项目初衷: 不是做剪辑器,而是做可复制的内容生产线

项目最早服务的是自营餐饮品牌的抖音本地生活内容生产: 每周大约有大量菜品特写素材,人工剪 500-1000 条短视频成本高、节奏不稳定、复用困难。dy-cut 的第一性目标是把“拍摄素材 → 批量混剪 → 人工复审 → 手动上传抖音”这条链路变成稳定流水线。

所以它一开始就不是一个自由拖拽的视频编辑器,也不是 SaaS 平台。它更像一个内容工厂的本地生产引擎: 配置可控、成本可算、结果可复审、错误可回滚。

Phase 1 的边界

  • 做: 素材导入、去重、抽帧、VLM 理解、LLM 文案、选片、渲染、导出、复审。
  • 不做: 抖音 OpenAPI 上传、多账号矩阵、SaaS、AI 配音、数据回传。
  • 产物: 只生成裸片,店名、POI、团购角标和水印留给抖音发布链路。
  • 原则: 所有关键调参走配置和可审计 JSON,不要把运营经验散落在代码里。

分支演进: 几条线分别解决什么问题

当前项目不是一条直线长出来的,而是从“稳定批量生产”逐步叠加“9:16 真实素材输入”“复审重生成”“灵感学习”“口播卡点”和“素材质量预处理”。理解分支差异,能帮助新人判断代码里哪些是主干生产能力,哪些是实验能力。

定位: 批量混剪主链路 + inspiration 灵感分析能力。包含本地素材导入、VLM/LLM、模板混剪、复审队列基础和对标视频学习沉淀。
适合: 看 Phase 1 的稳定生产边界,理解项目为什么强调配置、缓存、复审和成本控制。

关键变化: 从“样片能跑”走向“真实门店素材能批量跑”,同时把复审从只看结果扩展到能编辑字幕和排队重生成。

关键变化: 从“先选素材再叠 BGM”变成“口播 BGM 是骨架,素材卡到每个口播槽位”;这是最近两天探索最集中的方向。

三条工作线

1. 模板批量线

从 input/raw/<week> 读取素材,经 ingest、抽帧、VLM 理解、文案、差异化选片、render 和 export,生成可复审的批量成片。

适合稳定周产、模板化投放、黄金测试基线。

2. beatmix 探索线

以口播 BGM 的 ASR 槽位为骨架,让素材去卡“烤串、饮品、价格”等口播词。画面不是随便铺 BGM,而是跟着口播走。

适合验证更强节奏、更高商业信息密度的剪辑打法。

3. 素材质量线

在混剪前给素材打分、分层、标记负面风险和最佳片段,低分进入复审,不直接删除。它是素材库的“入库质检”。

适合把拍摄反馈、软淘汰和编排权重串起来。

主流程: 从原始素材到批量成片

核心步骤

  1. 素材入库: 把每周素材放进 input/raw/<week>,系统生成代理视频和导入索引。
  2. 画面理解: 抽关键帧,调用云端 VLM 识别菜品、动作、卖点和可用语义。
  3. 模板和文案: 套餐库、模板 YAML、BGM 池和文案共同决定每条片的表达方向。
  4. 差异化选片: 指纹维度约束重复度,避免一批视频看起来几乎一样。
  5. 渲染导出: ffmpeg 统一成 1080x1920 竖屏视频,输出到 output/<combo_id>/。
  6. 人工复审: Gradio UI 负责看成片、保留或退回。

运行命令

pip install -e ".[dev]"
cp .env.example .env

python -m src.orchestrator run --week 2026-W24
python -m src.ui.gradio_app

主链路的可调参数集中在 config/settings.yaml 和 config/templates/*.yaml,优先调配置,不要轻易改代码里的业务阈值。

最近两天重点一: beatmix 口播 BGM 卡点

beatmix 的范式变化是“BGM 不再只是背景音乐,而是剪辑骨架”。口播里说到“六十五串现烤烤串”时,画面应该是烤串;说到“两罐饮料”时,画面应该是饮品;说到价格、福利、口号时,画面用价格牌、包装、空镜或高转化补位。

输入结构

  • input/starter/*.mp4: 开头强钩子素材。
  • input/material/<batch>/tags.json: 内容素材标签。
  • config/bgm_voicemap/<bgm_id>.json: 口播槽位表。
  • cache/bgm/bgm_index.json: BGM 音频索引。

新机制

  • Top-K 候选: LLM 不只返回一个 clip,而是返回多个候选,本地按 seed 加权抽样,提高多样性。
  • slot category_hint: 槽位可指定 ["烤串"] 或 ["饮品"],解决全局 dish_categories 无法覆盖饮品口播的问题。
  • 历史 plan 去重: 读取旧 plan 指纹,避免同一 BGM 多次运行产出重复片。

运行命令

python -m src.orchestrator beatmix tag --dir input/material/2026-W24
python -m src.orchestrator beatmix score --dir input/material/2026-W24 --workers 4
python -m src.orchestrator beatmix mix --bgm bgm_core_01 --material-dir input/material/2026-W24

团队最佳实践

工程侧

  • 配置优先: 模板节奏、BGM 池、视频参数、diff 权重优先写在 YAML/settings,减少硬编码。
  • 旧链路和新实验隔离: beatmix 输入输出独立,验证稳定后再考虑并入主流程。
  • 任何批量删除先确认: 质量分是软淘汰依据,不能未经确认物理删除素材。
  • 产物可复盘: 成片旁边保留 plan/report,能追踪每个槽位为什么选这条素材。
  • 小步验证: 改 selector、dedup、render 时用单测和黄金样片一起守住回归。

运营/拍摄侧

  • 按槽位拍: 烤串、主菜、饮品、价格牌、包装、空镜都要独立成类。
  • 每条只讲一件事: 一条素材只表达一个动作或主体,方便算法卡口播。
  • 先清场再拍: 油污墙、杂物、品牌瓶、纸箱会显著拉低素材分。
  • 制造动作高点: 刷酱、撒料、夹起、切开、开盖、装盒都比静态俯拍更好剪。
  • 补齐转化镜头: 外卖盒、套餐全景、价格牌、饮品和配送到手,是 filler 槽位的关键素材。

新人上手路线

  1. 先读 README.md、docs/beatmix运行说明.md、docs/RUNBOOK.md,搞清楚主流程和 beatmix 是两条线。
  2. 跑一次主链路样片,确认本机依赖和 ffmpeg 可用。
  3. 看一份 tags.json,理解 category、dish、is_bspot、quality 的含义。
  4. 改一个 voicemap 槽位的 category_hint,再跑 beatmix,观察 plan.json 里素材选择是否更准。
  5. 看质量报告,把 D 类原因翻译成下一次拍摄 SOP。

后续值得深入的方向

1. 质量分真正参与渲染

当前 best_window 主要记录在标签和报告里。下一步应让 render 优先裁取最佳 1-2 秒,而不是默认中心裁剪。

2. 近重复聚类

把首帧/中帧 phash、菜品语义和历史 plan 结合起来,同组只优先用最高分素材,减少“看着像同一条”的成片。

3. 人工复审闭环

复审 UI 不只看成片,还应能批准/拒绝素材质量判断,把人工反馈写回标签。

4. 口播槽位语义增强

继续扩展饮品、价格、配送、门店环境、套餐全景等 category_hint,让 BGM 口播和素材库建立更精细的契约。

5. 投放数据反哺

未来接入发布后的播放、完播、转化数据,把“素材好不好”从主观评分升级为效果评分。

6. 拍摄 SOP 标准化

把质量报告中的负面原因转为门店拍摄清单,让素材源头稳定产生 B/A 类片段。
