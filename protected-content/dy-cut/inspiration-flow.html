Phase 1 · inspiration · 拍摄灵感 / 创意挖掘 · 2026-06-14

拆解爆款，反推创意

inspiration 不生产视频，而是产出一份每周「拍摄灵感报告」： 把抖音餐饮外卖的对标爆款逐条拆成视觉与内容因子，提炼规律， 再落成针对你每个套餐的、可执行的拍摄建议。 当前是竞品拆解（reactive），方向是AI agent 自主发掘 + 爆款溯源（proactive）。

当前实现状态

5流水线步骤：抓取 → 下载 → 分析 → 聚合 → 建议
2分析层：VLM 视觉/剪辑 + LLM 内容/情绪
1/周产出 output/inspiration/<week>.html
L0→L4从竞品拆解到自主创意 agent 的演进路线
创意来源 五步流程 拆解维度 代码映射 演进路线 如何运行
01 · Source

创意从哪来：现在 vs 未来

关键认知：现在是“别人已经火了我来拆”，未来是“agent 主动去发掘并溯源为什么火”。

现在 · reactive

竞品拆解

按固定关键词抓取/导入抖音餐饮外卖爆款 → 逐条 VLM+LLM 拆解视觉与内容 → 聚合本周规律 → 落到你套餐上的拍摄清单。创意来源是“已经火的视频”。

未来 · proactive

AI agent 自主发掘 + 溯源

由 agent 自主浏览同类视频、主动提出创意；尤其面向素材拍摄——做爆款特质溯源追踪（某条为什么火 → 拆到镜头/钩子/节奏/选品/发布时机的可复用因子），为拍摄与发布两端给建议。

02 · Pipeline

五步流水线

src/inspiration/，命令 python -m src.orchestrator inspire --week 2026-W24。

01

抓取

scraper.py

按关键词抓抖音(TikTokScraper，反爬时静默跳过)或读本地 metadata；播放量过滤 + 去重。

02

下载

downloader.py

yt-dlp 下载到 cache，已存在则跳过。

03

分析

analyzer.py

抽帧(1fps) → VLM 出视觉/剪辑层 + LLM 出内容层 → VideoAnalysis(缓存)。

04

聚合规律

reporter.py

全部分析喂 LLM → top 钩子 / 主导切镜区间 / 景别组合 / 情绪分布。

05

拍摄建议

reporter.py

逐套餐 3–5 条可执行建议(景别/运镜/时长/文案) → 渲染 HTML 报告。

03 · What we extract

单条视频拆解维度

VideoAnalysis：两层因子,是“爆款溯源”的原材料。

视觉 / 剪辑层 · VLM
  • shot_types 景别序列
  • camera_moves 运镜
  • lighting_style 光线风格
  • avg_cut_sec 平均切镜时长
  • transition_types 转场
  • bgm_tempo BGM 节奏
内容 / 情绪层 · LLM
  • hook_text 开头钩子
  • selling_points 卖点
  • cta_text 行动号召
  • emotion_arc 情绪弧:食欲冲击 / 信任建立 / 价格锚定 / 探店猎奇
04 · Code map

代码映射

模块与职责一一对应,方便接手与扩展。

scraper.py
TikTokScraper(在线抓取 + UA 轮换 + 反爬静默跳过) / LocalImporter(读 input/inspiration/metadata.json)。
downloader.py
yt-dlp 下载,缓存命中跳过。
analyzer.py
抽帧 + VLM 视觉分析 + LLM 内容分析,结果缓存 cache/inspiration/analysis/<id>.json(resume 复用)。
reporter.py
aggregate_patterns 聚合规律 + generate_shooting_suggestions 逐套餐建议 + render_html 出报告。
scheduler.py
每周一 8 点定时(schedule_day/hour),也内嵌在 Gradio 复审 UI 启动时一起跑。
05 · Roadmap

从“竞品拆解”到“自主创意 agent”

未来:agent 自主巡航、爆款溯源、拍摄+发布双向建议,最终形成数据回流闭环。

L0
竞品拆解
现在
给定关键词,被动抓取 → 拆解 → 周报建议。创意源自“已经火的视频”。
已实现
L1
主动发掘
agent 自主扩展关键词/账号/话题,持续巡航抖音外卖同类内容,而非固定关键词。
规划中
L2
爆款特质溯源
对“为什么火”做因子归因:钩子 × 选品 × 节奏 × 画面 × 发布时机,沉淀可复用「爆款因子库」。
规划中
L3
拍摄 / 发布双向建议
不止“拍什么”,还给“何时发、配什么文案/话题、A/B 哪个钩子”,并回流投放数据校正建议。
规划中
L4
闭环
灵感 → beatmix/run 出片 → 投放 → 数据回流 → 更新因子库 → 下一轮灵感,自我强化。
远期
落地抓手:L1 先把 scraper 从固定关键词升级为 agent 自主选题; L2 在 VideoAnalysis 上加“爆款因子”标注 + 跨周聚类溯源; L3 把 generate_shooting_suggestions 扩成“拍摄 + 发布”双 prompt,并接入投放回流数据。
06 · Run

如何运行

在线抓取被反爬时,用 --scraper local 手工塞对标视频。

python -m src.orchestrator inspire --week 2026-W24 [--scraper local|tiktok] [--force]

# 输入
config/settings.yaml > inspiration.{keywords, min_plays, weekly_limit, scraper}
input/inspiration/metadata.json        # local scraper 的对标视频元数据

# 输出
output/inspiration/<week>.html         # 每周拍摄灵感报告
cache/inspiration/analysis/<id>.json   # 单条分析缓存(删除才会重跑该条 VLM/LLM)
