## 客户只说了一句话

事情起得很小：公司销售同事要给本来生活系统做多地址导单。

订单表一份，商品 P 码表一份。收货人可能重复，商品要合并，价格和数量要用 `|` 拼起来，地址要拆出省、市、区，最后还要排成目标系统要求的固定字段。每一步都不难，但叠在一起就很磨人。

我先做了一个 Python 小工具。逻辑跑通，结果准确，导单表也能生成。站在工程师视角，这事已经解决了。

直到客户现场飘来一句：

> “这个还要装 Python 吗？我们每个人电脑环境都不一样，能不能直接打开就用？”

这句话不长，但挺重。它提醒我：我交付的不是一段脚本，而是一个人在真实工作里能不能少受一点折腾。

---

## 原来的痛点

原始流程大概是这样：

```text
订单表
  → 查商品 P 码
  → 按收货人 / 电话 / 地址分组
  → 多商品合并为一行
  → 编码 / 价格 / 数量用 | 拼接
  → 计算应付金额
  → 从地址里拆出区
  → 按系统模板导出 Excel
```

这种工作有几个特点：

| 特点 | 后果 |
|------|------|
| 规则固定 | 人做很烦，机器做正好 |
| 重复发生 | 每次都像从头再来 |
| 容易出错 | P 码、金额、地址错一处就返工 |
| 不创造销售价值 | 销售不该把时间耗在改表格上 |

所以第一版目标很朴素：把人从表格苦力里捞出来。

---

## 第一版：Python 把“算得对”解决了

Python 版很工程师。用 `pandas` 读订单表和商品表，建立商品名称到 P 码的映射，再按 `收货人 + 收货人电话 + 收货地址` 分组聚合，最后导出 Excel。

核心逻辑其实就三件事：

```text
清洗商品名 / P码
  → 按收货人聚合订单
  → 生成目标导单字段
```

它解决了不少业务细节：

- 商品名称去掉多余空格和换行
- P 码去掉隐藏换行
- 同一收货人的多个商品合并
- 商品编码、价格、数量用 `|` 拼接
- 自动计算买家应付货款
- 上海地址自动提取“XX区”
- 未匹配 P 码的商品在日志里提示

从技术上，它已经可用了。

但它的使用说明长这样：

```bash
pip install pandas xlrd openpyxl
python multi_address_order_tool.py 订单.xls 商品表.xlsx 输出.xlsx
```

对开发者来说，这几行命令没什么。对销售同事来说，这就是一堵墙。

```text
没有 Python
Python 版本不对
pip 装不上
依赖包报错
不知道命令行在哪
换一台电脑还要重来
```

我这才发现，所谓“自动化”，只是把 Excel 里的麻烦搬到了环境安装里。

---

## 真正的问题不是功能，而是摩擦

客户那句“能不能直接打开就用”，本质上不是功能需求，而是体验需求。

Python 版解决的是我熟悉的问题：数据清洗、分组聚合、Excel 导出。

客户真正关心的是：

- 不想安装环境
- 不想问 IT 要权限
- 不想学命令行
- 不想每台电脑都配一遍
- 只想上传两个 Excel，然后拿到结果

这就是纯技术流和 FDE 的分水岭。

纯技术流会问：逻辑是否正确？

FDE 还要追问：这个正确的逻辑，用户能不能顺手用起来？

---

## 第二版：和 Claude 聊了几句，改成纯 HTML

今天得空，我把这个痛点丢给 Claude。方向很快定了：不要服务器，不要 Python，不要安装包。做成一个 `index.html`，浏览器打开即可使用。

技术栈非常轻：

```html
<script src="https://cdn.jsdelivr.net/npm/xlsx@0.18.5/dist/xlsx.full.min.js"></script>
```

旧流程和新流程的差别很直观：

```text
旧版
安装 Python → 安装依赖 → 打开命令行 → 输入命令 → 生成 Excel

新版
双击 index.html → 上传订单表 → 上传 P 码表 → 点击生成 → 下载 Excel
```

这不是从“高级技术”退回“简单网页”。

这是从“工程师能跑”走向“客户能用”。

---

## 纯 HTML 版保留了业务逻辑，只换了交付形态

HTML 版没有改业务规则，只是把执行环境从 Python 搬到了浏览器。

用户看到的是两个上传区：

```text
订单表
  需含列：收货人、收货人电话、收货地址、商品名称、购买单价(元)、购买数量

商品信息表（带P码）
  需含列：礼包名称、P码
```

浏览器里用 SheetJS 读取 Excel：

```javascript
const wb = XLSX.read(e.target.result, { type: 'array' });
const ws = wb.Sheets[wb.SheetNames[0]];
const rows = XLSX.utils.sheet_to_json(ws, { defval: '' });
```

然后继续做那套熟悉的事情：

```text
读取 Excel
  → 建立 商品名称 → P码 映射
  → 按收货人 / 电话 / 地址分组
  → 合并商品编码、价格、数量
  → 计算金额
  → 导出结果 Excel
```

最后按目标系统字段顺序生成文件：

| 字段 | 处理方式 |
|------|----------|
| 商品编码 | 多商品用 `|` 拼接 |
| 商品价格 | 多价格用 `|` 拼接 |
| 商品数量 | 多数量用 `|` 拼接 |
| 买家应付货款 | 单价 × 数量后汇总 |
| 省 / 市 / 区 | 上海地址自动解析 |
| 邮费 | 默认 `0` |

这个改法最舒服的地方是：业务逻辑没丢，用户负担没了。

---

## 小交互，就是用户信心

纯 HTML 版里有一些很小的设计：

| 设计 | 用户感受 |
|------|----------|
| 拖拽上传 | 不用找复杂按钮 |
| 上传后绿色提示 | 我知道文件已经选中了 |
| 条件不足时按钮禁用 | 我不会误点 |
| 分步骤处理日志 | 我知道工具正在干什么 |
| 统计卡片 | 我知道输入多少、输出多少 |
| 未匹配商品警告 | 我能快速定位问题 |
| 下载按钮最后出现 | 下一步动作很明确 |

这些都不是大功能，但会让用户踏实。

工具最怕的不是报错，而是用户不知道它在干什么。易用性不是“好看一点”，而是让用户在不确定里少慌一点。

---

## 从 Python 到 HTML，不是技术降级，是交付升级

| 维度 | Python 版 | HTML 版 |
|------|-----------|---------|
| 安装成本 | 需要 Python 和依赖 | 无需安装 |
| 使用入口 | 命令行 | 浏览器双击 |
| 跨电脑复制 | 依赖环境一致 | 复制一个 HTML 即可 |
| 用户理解成本 | 高 | 低 |
| 适合人群 | 开发者、懂电脑的人 | 销售、运营、业务同事 |

FDE 的第一课就在这里：

> 不是把最强的技术交给客户，而是把客户刚好能顺手拿起来的技术交给客户。

很多需求不是“大功能”，而是“小阻力”：

- 少装一个软件
- 少问一次 IT
- 少复制一列
- 少改一个表头
- 少担心一次金额算错
- 少在命令行里迷路

这些小阻力加起来，就是用户愿不愿意继续用你的产品。

---

## AIcoding 的价值：把迭代速度推到客户反馈的节奏上

如果没有 AI，这个改版当然也能做。

但 AIcoding 带来的变化是：我不用把它排进正式开发周期，不用先搭框架，不用把小工具做成大项目。

只要把真实痛点说清楚：

```text
现有 Python 脚本能处理订单表和商品 P 码表，
但销售同事在不同电脑上安装 Python 和依赖成本太高。
请改成一个纯 HTML 工具，浏览器打开即可上传两个 Excel，
在前端完成聚合、P 码匹配、地址解析，并下载结果 Excel。
```

Claude 很快就能帮我把 Python 逻辑迁移成浏览器端实现。

这不是“AI 替我写代码”这么简单。更重要的是，它让开发节奏贴近客户反馈：

```text
客户说卡住
  → 当天复盘痛点
  → 当天改出可用版本
  → 当天给用户试
  → 继续磨掉下一处摩擦
```

需求不再只是文档里写出来的，而是在用户手边长出来的。

---

## 这次真正的收获

这次没有复杂架构，也没有炫目的技术创新。

只有一个朴素的小工具：

```text
两个 Excel 进去，一个导单 Excel 出来。
```

但它让我完成了一次很明显的思想跃迁。

以前我更关心：

- 数据结构对不对
- 算法逻辑稳不稳
- 代码拆分优不优雅
- 依赖选型合不合理

现在我会多问一句：

- 用户要不要安装东西？
- 用户知道下一步点哪吗？
- 出错时用户能不能自己判断？
- 换一台电脑还能不能用？
- 这个工具能不能不解释也用起来？

客户那句“能不能直接打开就用”，像一只手，把我从代码里拎出来，放回了现场。

Python 版解决了“算得对”。

HTML 版解决了“用得上”。

而 FDE 要做的，是把这两件事连起来：

```text
业务痛点 → 快速原型 → 用户试用 → 降低摩擦 → 再贴近一步
```

从这个小小的多地址导单工具开始，我对“易用性”这三个字有了更实在的理解。

它是销售同事在忙到头大的时候，双击一个文件，上传两个 Excel，点一下生成，然后轻轻说一句：

> “这个舒服。”

这就够了。
